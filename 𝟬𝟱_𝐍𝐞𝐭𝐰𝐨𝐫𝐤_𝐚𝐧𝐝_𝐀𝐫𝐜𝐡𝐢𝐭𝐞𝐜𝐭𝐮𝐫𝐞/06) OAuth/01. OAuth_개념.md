## 오어스
# 01 `OAuth`란?
→ 카카오, 구글, 네이버처럼 이미 계정이 있는 서비스를 이용해 다른 앱에 로그인하는 방식으로 로그인이 성공하면 카카오나 구글이 앱에 로그인 성공 정보를 전달

# 02 일반 로그인과 `OAuth` 로그인
### ① 일반 로그인
```
사용자
  ↓ 아이디와 비밀번호 입력
내 앱
  ↓ 로그인 정보 전송
내 서버
  ↓ 로그인 결과 전달
내 앱
```
일반 로그인에선 내 앱이나 서버가 사용자의 아이디와 비번을 직접 처리해야 함
### ② `OAuth` 로그인
```
사용자
  ↓ 카카오·구글 로그인
카카오·구글
  ↓ 로그인 성공 정보 전달
내 앱
```
하지만 OAuth에선 카카오·구글이 로그인을 처리하기 때문에 내 앱은 사용자의 카카오·구글 비번을 알 수 ❌

# 03 `OAuth`를 사용하는 이유
**✨ <OAuth를 사용하면 다음과 같은 장점이 있음>**
* 회원가입 과정을 줄일 수 있음
* 사용자가 새 비번을 직접 만들 필요가 없음
* 비번을 내 앱이 직업 관리하지 않아도 됨
* 카카오·구글 계정으로 빠르게 로그인 가능
* 로그인 보안을 전문 서비스에 맡길 수 있음
#### 우리를 봐보자 🐔 <sub> 나같은 경우 귀찮아서 회원가입을 보단 구글 로그인이나 카톡 로그인으로 끝낸다 버튼만 몇 번 누르면 되므로 즉, 엄청 간편하고 편함 !</sub>

# 04 `OAuth`에 등장하는 역할
오어스에는 여러 역할이 있음
> 사용자 → 내 앱 → 카카오·구글

| 용어 | 의미 | 예시 |
| :--- | :---: | :---: |
| **사용자 (Resource Owner)** | 로그인하려는 사람 | 앱을 사용하는 학생 |
| **Client** | OAuth 로그인을 사용하는 앱 | 내가 만드는 Swift 앱 |
| **Provider** | 로그인을 제공하는 서비스 | 카카오, 구글, 네이버 |
| **Resource Server** | 사용자 정보를 보관하는 서버 | 카카오 사용자 정보 서버 |
| **Authorization Server** | 로그인과 권한을 확인하는 서버 | 구글 로그인 서버 |

지금은 아래 3가지만 기억해도 됨 (나중에 하면서 천천히 더 외우기)
* **사용자** : 로그인하는 사람
* **Client** : 내 앱
* **Provider** : 카카오·구글·네이버

# 05 로그인 흐름
1. 사용자가 내 앱에서 "카카오로 로그인"을 누름
2. 내 앱이 카카오 로그인 화면을 엶
3. 사용자가 카카오에서 로그인 함
4. 카톡이 사용자에게 정보 제공 동의를 요청
5. 사용자가 동의
6. 카카오가 로그인 성공 결과를 내 앱에 전달
7. 내 앱이 로그인 상태를 저장

# 06 `Access Token`이란?
→ `Access Token`은 사용자가 로그인했다는 것을 증명하는 일종의 출입증이라 할 수 있음
```
로그인 성공
    ↓
Access Token 발급
    ↓
내 앱이 토큰 보관
    ↓
사용자 정보 요청
```
> ex.) 앱이 카카오에 사용자 정보를 요청할 때 `Access Token`을 함께 보냄
```
내 앱 ── Access Token과 함께 요청 ──> 카카오
내 앱 <── 사용자 정보 ───────────── 카카오
```
`Access Token` 자체가 사용자의 비밀번호는 아니고 **사용자를 대신해 허용된 기능을 사용할 수 있는 인증 정보**라고 기억하고 잇으면 됨

# 07 `Scope`란?
→ `Scope`는 내 앱이 어떤 사용자 정보를 사용할 수 있는지 정하는 범위
- 이메일
- 닉네임
- 프로필 사진
- 생일
등등 이런 정보가 있을 수 있음


앱이 모든 정보를 마음대로 가져가는 건 아니고 필요한 정보만 요청해야함
```
내 앱이 요청:
"닉네임과 프로필 사진을 사용해도 될까요?"

사용자:
"동의"
```
사용자가 동의한 범위 안에서만 정보를 사용 가능함

# 08 `Authorization Code`란?
일부 오어스 방식에선 로그인 성공 후 바로 `Access Token`을 주지 않고 먼저 `Authorization Code`를 전달함
> 로그인 성공 → Authorization Code 발급 → 내 앱 또는 서버가 code 전달 → Access Token 발급

> - 흐름은 다음과 같음 \
> 사용자 → 카카오·구글 로그인 → Authorization Code → 내 앱 또는 내 서버 → Access Token 요청 → Access Token 발급

Authorization Code는 보통 한 번만 사용하고 짧은 시간 동안만 유효하마

# 11 OAuth와 회원가입의 관계
→ OAuth 로그인은 회원가입도 간단하게 만들어줌

# 12 주의할 점
* Access Token을 다른 사람에게 노출하면 안됨
* 필요한 정보만 요청하기
- 로그인 제공자의 설정값을 정확히 등록
- 로그아웃과 회원 탈퇴를 구분
- Access Token이 만료될 수 있다는 점 기억
- 앱의 Bundle ID????나 Redirext URL?을 정확하게 설정

# 13 정리
* `OAuth`란 : <mark>카카오·구글·네이버 같은 외부 서비스가 로그인을 대신 처리</mark>하도록 하는 방식

#### ✨ 주요 용어
* **Client** : 내 앱
* **Provider** : 카카오·구글·네이버
* **Access Token** : 로그인 성공을 증명하는 출입증
* **Scope** : 앱이 사용할 수 있는 정보의 범위
* **Authorization Code** : Access Token을 받기 전에 전달되는 임시 코드

#### 🍀 전체 흐름
> **로그인 버튼 클릭** \
> → 카카오·구글 로그인 \
> → 사용자 동의 \
> → 인증 코드 또는 Access Token 발급 \
> → 내 앱이 로그인 결과 확인 \
> → 로그인 완료
