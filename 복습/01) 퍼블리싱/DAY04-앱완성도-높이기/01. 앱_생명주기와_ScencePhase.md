### Ⅰ. 앱 생명주기와 `ScenePhase`

<br>


# 1-1 앱 생명주기란?

→ 앱이 <mark>실행되고 사용되다가 잠시 멈추거나 종료되는 상태의 흐름</mark>임

앱은 항상 화면에 떠 있는 것이 아니라 사용자의 동작에 따라 상태가 바뀜


> 앱 실행 → 화면에 보임 → 다른 앱으로 이동하거나 화면이 가려짐 → 다시 화면에 보임

앱의 상태에 따라 작업을 시작하거나 멈춰야 할 수 있음


<br>
<br>


# 1-2 앱 상태를 알아야 하는 이유

앱이 화면에 보이지 않을 때도 모든 작업을 계속하면 배터리와 자원을 불필요하게 사용할 수 있음

예를 들어 치이카와 목록을 새로고침하는 중에 사용자가 다른 화면으로 이동하면 작업을 계속할지 잠시 멈출지 고려해야 함

- 화면에 보일 때 필요한 데이터 불러오기
- 화면이 가려졌을 때 불필요한 작업 줄이기
- 앱으로 돌아왔을 때 화면 상태 확인하기


<br>
<br>


# 1-3 `ScenePhase`란?

→ SwiftUI에서 앱의 현재 실행 상태를 확인할 수 있게 해주는 값

`ScenePhase`로 앱이나 화면이 현재 활성 상태인지, 비활성 상태인지 백그라운드에 있는지 확인할 수 있음

주요 상태는 다음과 같음

- `active` : 앱이 앞에 있고 사용자의 입력을 받을 수 있음
- `inactive` : 앱이 활성 상태에서 벗어나는 중이거나 일시적으로 입력을 받지 않는 상태
- `background` : 앱이 화면 뒤로 이동한 상태


<br>
<br>

# 1-4 `ScenePhase` 읽기

SwiftUI에서는 `@Environment`를 사용해 현재 `ScenePhase`를 읽을 수 있음

```swift
@Environment(\.scenePhase) private var scenePhase
```

`scenePhase` 값을 사용하면 앱의 상태가 바뀌었을 때 필요한 처리 가능



<br>
<br>


# 1-5 상태 변화에 반응하기

`.onChange`를 사용하면 `scenePhase`가 바뀔 때 원하는 작업을 실행할 수 있음

```swift
.onChange(of: scenePhase) { _, newPhase in
    if newPhase == .active {
        print("앱이 다시 활성화 됨")
    }
}
```

예를 들어 앱으로 돌아왔을 때 치이카와 목록을 새로고침하도록 연결할 수 있음


<br>
<br>



# 1-6 상태에 따라 할 수 있는 작업

앱 상태에 따라 필요한 동작을 다르게 정할 수 있음

- `active` : 화면을 다시 보여주거나 필요한 데이터를 갱신함
- `inactive` : 잠시 입력을 받지 않는 상황에 대비함
- `background` : 꼭 필요하지 않은 갱신이나 작업을 줄임

어떤 작업을 수행할지는 앱의 기능과 사용자 경험에 맞춰 정해야 함



<br>
<br>


# 1-7 앱 생명주기와 비동기 작업

앱이 백그라운드로 이동한다고 해서 실행 중인 모든 작업이 항상 즉시 종료되는 것은 아님  
작업이 계속 필요한지 확인하고 필요 없어진 작업은 취소하거나 결과 반영을 막을 수 있음

예를 들어 검색 화면을 벗어났다면 이전 검색 결과가 나중에 화면 상태를 덮지 않도록 처리할 수 있음


<br>
<br>


# 1-8 정리 ✨

* 앱 생명주기는 앱이 실행되고 화면에 보이거나 백그라운드로 이동하는 상태의 흐름
* `ScenePhase`는 SwiftUI에서 현재 앱 상태를 확인할 때 사용함
* `active`는 앱을 사용할 수 있는 상태
* `inactive`는 일시적으로 입력을 받지 않는 상태
* `background`는 앱이 화면 뒤에 있는 상태임
* 상태가 바뀔 때 필요한 작업을 수행하고 불필요한 작업은 줄일 수 있음

<br>

> ### ⇒ 앱 상태를 확인하면 화면에 보일 때와 백그라운드에 있을 때 필요한 동작을 나눠 처리할 수 있음 ✨
