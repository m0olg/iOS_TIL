### Ⅱ. 프로토콜과 테스트용 객체




# 2-1 프로토콜이란?

→ 타입이 따라야 할 기능의 규칙을 정해두는 것

프로토콜에는 필요한 메서드나 프로퍼티를 선언함  
프로토콜을 채택한 타입은 그 규칙에 맞춰 기능을 구현해야 함

```swift
protocol CharacterService {
    func fetchCharacters() async throws -> [Character]
}
```

이 프로토콜은 캐릭터 목록을 가져오는 기능이 있어야 한다는 규칙을 정함






# 2-2 프로토콜을 채택한 실제 서비스

실제 서버와 통신하는 객체가 프로토콜을 채택할 수 있음

```swift
final class CharacterAPIClient: CharacterService {
    func fetchCharacters() async throws -> [Character] {
        // 서버에 요청하고 응답을 디코딩
        []
    }
}
```

`CharacterAPIClient`는 `CharacterService`의 `fetchCharacters()`를 구현함






# 2-3 테스트용 객체란?

→ 테스트할 때 실제 서버 대신 사용할 가짜 객체

테스트용 객체는 서버에 연결하지 않고 미리 정해둔 데이터를 반환할 수 있음

```swift
final class MockCharacterService: CharacterService {
    func fetchCharacters() async throws -> [Character] {
        [
            Character(id: 1, name: "집가고"),
            Character(id: 2, name: "싶다")
        ]
    }
}
```

테스트할 때마다 같은 결과를 받을 수 있어 ViewModel의 동작을 확인하기 쉬움






# 2-4 실제 서비스와 테스트용 객체 비교

둘 다 `CharacterService`를 따르지만 동작 방식이 다름

- `CharacterAPIClient`: 실제 서버에 요청함
- `MockCharacterService`: 미리 정한 테스트 데이터를 반환함

```
같은 프로토콜
├── 실제 서버용 객체
└── 테스트용 객체
```






# 2-5 ViewModel에 프로토콜 전달하기

ViewModel이 구체적인 APIClient 대신 프로토콜을 사용하도록 만들 수 있음

```swift
@MainActor
final class CharacterViewModel {
    private let service: CharacterService
    private(set) var characters: [Character] = []

    init(service: CharacterService) {
        self.service = service
    }

    func loadCharacters() async {
        do {
            characters = try await service.fetchCharacters()
        } catch {
            characters = []
        }
    }
}
```

ViewModel은 전달받은 서비스가 실제 서버용인지 테스트용인지 몰라도 됨  
프로토콜에 정한 기능만 사용하면 됨
