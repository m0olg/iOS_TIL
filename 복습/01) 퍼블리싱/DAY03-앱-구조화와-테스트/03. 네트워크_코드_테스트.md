### Ⅲ. 네트워크 코드 테스트

<br>


# 3-1 네트워크 코드를 테스트하는 이유

> 네트워크 코드가 서버에 요청을 보내고 응답을 처리하는 과정에서 문제가 없는지 확인해야 함

실제 서버만 이용해 테스트하면 인터넷이나 서버 상태에 따라 결과가 달라질 수 있음  
그래서 <u>서버에 연결하지 않고도 앱의 데이터 처리 흐름을 확인하는 방법이 필요</u>함

<br>
<br>



# 3-2 테스트에서 확인할 내용

네트워크 기능을 테스트할 때는 다음 내용을 확인할 수 있음

- 데이터를 성공적으로 받아오는지
- 응답 데이터가 모델로 잘 변환되는지
- 응답이 비어 있을 때 알맞게 처리하는지
- 요청에 실패했을 때 오류 상태를 보여주는지


<br>
<br>


# 3-3 실제 서버 테스트의 한계

실제 서버에 요청을 보내면 테스트 결과가 서버나 네트워크 상황에 영향을 받을 수 있음

- 인터넷 연결이 필요함
- 서버가 일시적으로 중단될 수 있음
- 서버의 데이터가 변경될 수 있음
- 테스트 중 서버에 실제 데이터가 저장될 수 있음

따라서 ViewModel의 데이터 처리 동작을 확인할 때는 테스트용 객체를 사용할 수 있음


<br>
<br>


# 3-4 테스트용 서비스 준비하기

테스트용 서비스는 프로토콜을 따르면서 원하는 결과를 반환함

```swift
protocol CharacterService {
    func fetchCharacters() async throws -> [Character]
}

final class MockCharacterService: CharacterService {
    func fetchCharacters() async throws -> [Character] {
        [
            Character(id: 1, name: "학교가고"),
            Character(id: 2, name: "싶다")
        ]
    }
}
```

`MockCharacterService`는 서버에 요청하지 않고 정해둔 배열을 반환함

<br>
<br>



# 3-5 ViewModel에 테스트용 서비스 전달하기

ViewModel이 프로토콜을 통해 서비스를 받도록 만들면 실제 서비스와 테스트용 서비스를 바꿔서 사용할 수 있음

```swift
@MainActor
final class CharacterViewModel {
    private let service: CharacterService
    private(set) var characters: [Character] = []

    init(service: CharacterService) {
        self.service = service
    }

    func loadCharacters() async {
        do {
            characters = try await service.fetchCharacters()
        } catch {
            characters = []
        }
    }
}
```

테스트할 때는 `MockCharacterService`를 전달

```swift
let viewModel = CharacterViewModel(
    service: MockCharacterService()
)
```

<br>
<br>



# 3-6 성공 결과 확인하기

ViewModel의 함수를 실행한 뒤 데이터가 예상대로 저장됐는지 확인함

```swift
await viewModel.loadCharacters()

assert(viewModel.characters.count == 2)
assert(viewModel.characters[0].name == "학교가고")
```

`assert` 조건이 참이면 테스트를 계속 진행하고 거짓이면 문제가 있는 것으로 확인할 수 있따


<br>
<br>


# 3-7 실패 결과 확인하기

실패 상황을 확인하려면 오류를 던지는 테스트용 서비스를 만들 수 있음

```swift
enum TestError: Error {
    case failed
}

final class FailingCharacterService: CharacterService {
    func fetchCharacters() async throws -> [Character] {
        throw TestError.failed
    }
}
```

실패용 서비스를 ViewModel에 전달하면 요청이 실패했을 때 오류 처리가 제대로 되는지 확인할 수 있음






# 3-8 테스트할 때 주의할 점

- 성공과 실패 상황을 각각 확인하기
- 서버에 연결하지 않아도 반복해서 같은 결과가 나오도록 하기
- 테스트가 실제 서버 데이터를 바꾸지 않도록 하기
- 목록이 비어 있는 경우도 별도로 확인하기
- 오류가 났을 때 ViewModel 상태나 안내 문구가 알맞게 바뀌는지 확인하기






# 3-9 정리 ✨

* 네트워크 코드는 성공·빈 결과·실패 상황을 나누어 확인할 수 있음
* 실제 서버는 네트워크와 서버 상태에 따라 테스트 결과가 달라질 수 있음
* 프로토콜을 사용하면 테스트용 서비스를 전달할 수 있음
* Mock 객체는 서버에 연결하지 않고 미리 정한 데이터를 반환함
* 테스트용 객체를 사용하면 ViewModel의 데이터 처리와 오류 대응을 반복해서 확인하기 쉬움

> ### ⇒ 테스트용 서비스를 사용하면 실제 서버에 연결하지 않고도 네트워크 결과에 따른 앱 동작을 확인할 수 있음 ✨
