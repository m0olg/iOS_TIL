### Ⅰ. 의존성 주입




# 1-1 의존성이란?

→ 한 타입이 다른 타입의 기능을 사용하는 관계

예를 들어 `CharacterViewModel`이 서버에서 캐릭터 목록을 가져오려고 `APIClient`를 사용한다면 `CharacterViewModel`은 `APIClient`에 의존함


> CharacterViewModel → APIClient를 사용함






# 1-2 의존성을 직접 만드는 방식

ViewModel 안에서 필요한 객체를 직접 만들 수 있음

```swift
final class CharacterViewModel {
    private let apiClient = CharacterAPIClient()
}
```

코드가 간단해 보이지만 `CharacterViewModel`이 `CharacterAPIClient`에 직접 연결됨  
<mark>테스트하거나 다른 구현으로 바꾸고 싶을 때 수정하기 어려워질 수 있음</mark>






# 1-3 의존성 주입이란?

→ 필요한 객체를 타입 내부에서 직접 만들지 않고 외부에서 전달받는 방식

```swift
final class CharacterViewModel {
    private let service: CharacterService

    init(service: CharacterService) {
        self.service = service
    }
}
```

`CharacterViewModel`은 서비스를 직접 만들지 않고 초기화할 때 전달받음




# 1-4 초기화로 의존성 전달하기

객체를 만들 때 필요한 의존성을 `init`에 전달할 수 있음

```swift
let service = CharacterAPIClient()
let viewModel = CharacterViewModel(service: service)
```

이렇게 하면 ViewModel이 어떤 서비스를 사용할지 바깥에서 정할 수 있음 !!






# 1-5 의존성 주입의 장점

- 실제 서버용 객체와 테스트용 객체를 바꿔 사용할 수 있음
- ViewModel이 특정 구현에 덜 묶임
- 각 타입의 역할을 나누기 쉬움
- 테스트할 때 실제 서버에 연결하지 않아도 됨
- 필요한 객체가 무엇인지 초기화 코드에서 확인할 수 있음






# 1-6 의존성 주입과 프로토콜

주입할 타입을 구체적인 클래스가 아니라 프로토콜로 선언하면 여러 구현을 같은 방식으로 사용할 수 있음

```swift
protocol CharacterService {
    func fetchCharacters() async throws -> [Character]
}

final class CharacterAPIClient: CharacterService {
    func fetchCharacters() async throws -> [Character] {
        // 서버에서 캐릭터 목록 요청
        []
    }
}
```

> `CharacterViewModel`은 `CharacterService`를 따르는 객체라면 어떤 구현이든 전달받을 수 있음






# 1-7 정리 ✨

* 의존성은 한 타입이 다른 타입의 기능을 사용하는 관계
* 의존성 주입은 필요한 객체를 외부에서 전달받는 방식
* 초기화 시 객체를 전달하면 사용할 구현을 바꾸기 쉬움
* 프로토콜을 통해 의존성을 주입하면 실제 서비스와 테스트용 서비스를 같은 규칙으로 사용할 수 있음

> ### ⇒ 필요한 객체를 안에서 직접 만들지 않고 밖에서 전달받으면 코드를 바꾸고 테스트하기 쉬워짐 ✨
