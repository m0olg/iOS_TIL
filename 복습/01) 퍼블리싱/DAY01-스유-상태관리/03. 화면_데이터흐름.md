### Ⅲ. 화면 데이터 흐름




# 3-1 화면 데이터 흐름이란?

→ 데이터가 어디서 만들어지고 어떻게 화면에 전달되는지 정리하는 것

예를 들어 치이카와 목록을 보여주는 화면이라면 다음처럼 흐를 수 있음


> 서버에서 목록 받기 → ViewModel에 저장 → View가 목록을 화면에 표시






# 3-2 View와 ViewModel의 역할

### 1) View

화면을 그리고 사용자 동작을 전달함

- 목록이나 버튼 표시
- 검색어 입력 받기
- 버튼을 눌렀을 때 ViewModel에 동작 요청

### 2) ViewModel

화면에 필요한 데이터와 상태를 관리함

- 서버에 데이터 요청
- 응답 데이터 저장
- 로딩·성공·빈 결과·실패 상태 관리






# 3-3 데이터가 화면에 표시되는 과정

치이카와 목록을 화면에 띄운다고 하면 다음처럼 동작함


> View가 ViewModel에 목록 요청 → ViewModel이 서버에서 데이터 받음 → ViewModel의 목록이 바뀜 → View가 변경을 감지해 화면을 갱신

화면은 서버에 직접 요청하기보다 ViewModel을 통해 데이터를 받도록 구성할 수 있음






# 3-4 사용자 입력이 ViewModel로 전달되기

검색창에 입력한 값이나 버튼을 누른 동작은 View에서 ViewModel로 전달할 수 있음


> 사용자가 "하치와레" 입력 → View가 검색어를 ViewModel에 전달 → ViewModel이 검색 요청

View는 사용자가 무엇을 했는지 전달하고, ViewModel은 그 동작에 필요한 처리를 함






# 3-5 ViewModel에서 화면 데이터 관리하기

ViewModel은 화면에 표시할 데이터를 프로퍼티로 관리할 수 있음

```swift
@Observable
final class CharacterViewModel {
    var characters: [Character] = []
    var isLoading = false
}
```

`characters`는 화면에 보여줄 캐릭터 목록이고 `isLoading`은 데이터를 불러오는 중인지 나타냄






# 3-6 상태 변화에 따라 화면 달라지기

요청 결과에 따라 ViewModel의 값이 바뀌고 화면도 그 값에 맞게 달라질 수 있음


> isLoading = true → 로딩 화면 표시 \
> characters에 데이터가 있음 → 캐릭터 목록 표시 \
> characters가 비어 있음 → 빈 결과 안내 표시

이처럼 View는 ViewModel의 데이터를 바탕으로 현재 화면을 구성함






# 3-7 양방향 데이터 연결

검색창처럼 사용자가 값을 입력하고 화면도 그 값을 계속 보여줘야 하는 경우 `Binding`으로 연결할 수 있음

```swift
@State private var keyword = ""

TextField("캐릭터 검색", text: $keyword)
```

사용자가 입력하면 `keyword`가 바뀌고 그 값이 화면에도 반영됨

`Binding`은 상태를 소유한 곳과 그 상태를 사용하는 곳을 연결해줌






# 3-8 데이터 흐름을 한 방향으로 유지하기

화면에서 사용자 동작을 전달하고 ViewModel에서 데이터를 바꾼 뒤 다시 화면에 보여주는 방식으로 흐름을 정리할 수 있음


> 사용자 동작 → ViewModel의 기능 실행 → 상태 변경 → View 갱신

이렇게 흐름을 단순하게 정리하면 데이터가 어디서 바뀌는지 찾기 쉬워짐






# 3-9 화면에서 ViewModel 사용하기

SwiftUI View에서 ViewModel을 사용하면 ViewModel의 상태에 따라 화면을 구성할 수 있음

```swift
struct CharacterListView: View {
    @State private var viewModel = CharacterViewModel()

    var body: some View {
        List(viewModel.characters) { character in
            Text(character.name)
        }
    }
}
```

`viewModel.characters`에 새 데이터가 들어오면 목록도 그에 맞게 갱신됨  
이 예시의 `Character`는 목록에서 구분할 수 있는 식별자를 제공해야 함






# 3-10 화면 데이터 흐름에서 주의할 점

- View가 네트워크 요청과 데이터 처리를 모두 떠안지 않게 역할을 나눔
- 화면에 필요한 데이터와 상태를 ViewModel에서 관리함
- 상태를 바꾸는 곳을 명확하게 해 데이터 흐름을 따라가기 쉽게 함
- ViewModel의 데이터가 바뀌었을 때 View가 변경을 감지할 수 있게 구성함
- UI에 연결된 상태를 갱신할 때는 메인 액터에서 처리해야 할 수 있음






# 3-11 정리 ✨

* View는 화면을 표시하고 사용자의 동작을 ViewModel에 전달함
* ViewModel은 화면에 필요한 데이터와 상태를 관리함
* 사용자의 입력이나 버튼 동작에 따라 ViewModel의 기능이 실행됨
* ViewModel의 데이터가 바뀌면 View가 그 변화를 반영해 화면을 갱신함
* 데이터 흐름을 정리하면 상태가 어디서 바뀌는지 파악하기 쉬움

> ### ⇒ View가 동작을 전달하면 ViewModel이 데이터를 바꾸고, View는 바뀐 데이터로 화면을 다시 보여줌 ✨
