### Ⅱ. `Observable`과 `ObservableObject`


<br>

# 2-1 왜 필요한가?????

`@State`는 한 View 안에서 사용하는 간단한 상태에 잘 맞음  
하지만 여러 화면에서 같이 쓰는 데이터나 기능이 많은 상태는 별도의 타입으로 관리하면 편함

예를 들어 치이카와 목록을 불러오고 검색어와 로딩 상태까지 관리한다면 View 안에 전부 두기보다 모델 객체로 나눌 수 있음 !


<br>
<br>


# 2-2 `Observable`이란?

→ 타입의 데이터가 바뀌었을 때 그 데이터를 사용하는 SwiftUI 화면이 변경을 감지할 수 있게 하는 기능

```swift
import Observation

@Observable
final class CharacterViewModel {
    var characters: [String] = []
    var isLoading = false
}
```

`@Observable`을 붙이면 이 타입의 프로퍼티 변화를 SwiftUI가 관찰할 수 있음


<br>
<br>


# 2-3 `Observable` 사용하기

SwiftUI View에서 `@Observable` 객체를 상태로 보관해 사용할 수 있음

```swift
import SwiftUI
import Observation

@Observable
final class CharacterViewModel {
    var characters = ["치이카와", "하치와레", "우사기"]
}

struct CharacterListView: View {
    @State private var viewModel = CharacterViewModel()

    var body: some View {
        List(viewModel.characters, id: \.self) { character in
            Text(character)
        }
    }
}
```

`viewModel.characters`가 바뀌면 해당 값을 사용하는 화면이 다시 표시될 수 있음


<br>
<br>


# 2-4 `ObservableObject`란?

→ 객체의 변경을 SwiftUI에 알려주는 프로토콜

`ObservableObject`를 채택한 클래스는 `@Published` 프로퍼티를 사용해 값의 변화를 알릴 수 있음

```swift
final class CharacterViewModel: ObservableObject {
    @Published var characters: [String] = []
    @Published var isLoading = false
}
```

- `ObservableObject`: 객체가 변경 사항을 알릴 수 있도록 함
- `@Published`: 값이 바뀔 때 변경을 알릴 프로퍼티에 붙임


<br>
<br>


# 2-5 `ObservableObject`를 View에서 사용하기

View가 객체를 직접 소유한다면 `@StateObject`로 만들 수 있음

```swift
struct CharacterListView: View {
    @StateObject private var viewModel = CharacterViewModel()

    var body: some View {
        List(viewModel.characters, id: \.self) { character in
            Text(character)
        }
    }
}
```

`@StateObject`는 View의 생명주기 동안 객체를 유지  
`@Published` 프로퍼티가 바뀌면 View가 변경을 감지


<br>
<br>


# 2-6 다른 View에서 객체 전달받기

부모 View가 만든 `ObservableObject`를 자식 View에서 전달받아 사용할 때는 `@ObservedObject`를 쓸 수 있음

```swift
struct CharacterListView: View {
    @ObservedObject var viewModel: CharacterViewModel

    var body: some View {
        List(viewModel.characters, id: \.self) { character in
            Text(character)
        }
    }
}
```

보통 부모 View가 객체의 생성을 맡고 자식 View는 전달받은 객체를 관찰함

<br>

<br>


# 2-7 `Observable`과 `ObservableObject` 비교

- `@Observable`: Observation 프레임워크를 사용하는 방식
- `ObservableObject`: Combine의 프로토콜과 `@Published`를 사용하는 방식
- `ObservableObject` 객체를 View에서 소유할 때는 보통 `@StateObject`를 사용함
- 전달받은 객체를 관찰할 때는 보통 `@ObservedObject`를 사용함

둘 중 어떤 방식을 쓸지는 프로젝트에서 사용하는 Swift와 SwiftUI 방식에 따라 달라질 수 있음


<br>
<br>


# 2-8 정리

* 복잡하거나 여러 View에서 사용하는 상태는 별도의 모델 타입으로 관리할 수 있음
* `@Observable`은 프로퍼티 변화를 SwiftUI가 관찰하게 함
* `ObservableObject`는 객체의 변경을 알리고 `@Published`로 프로퍼티 변화를 알림
* `@StateObject`는 `ObservableObject` 객체를 View가 소유할 때 사용함
* `@ObservedObject`는 다른 곳에서 만든 객체를 View가 전달받아 관찰할 때 사용함

<br>

> ### ⇒ `Observable`과 `ObservableObject`는 데이터가 바뀌었을 때 화면이 그 변화를 알아차리게 도와줌 ✨
