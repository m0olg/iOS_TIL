### Ⅰ. `State`와 `Binding`




# 1-1 상태란?

→ 앱 화면에 영향을 주는 값

예를 들어 버튼을 눌렀는지, 검색어를 입력했는지, 치이카와 목록을 불러왔는지 같은 값이 상태가 될 수 있음

상태가 바뀌면 화면도 그 값에 맞게 다시 표시되어야 함


> 상태가 바뀜 → SwiftUI가 변경을 감지 → 화면을 다시 그림






# 1-2 `@State`란?

→ View가 직접 소유하는 간단한 상태를 관리할 때 사용하는 프로퍼티 래퍼

```swift
struct CharacterView: View {
    @State private var isFavorite = false

    var body: some View {
        Button(isFavorite ? "찜 해제" : "찜하기") {
            isFavorite.toggle()
        }
    }
}
```

버튼을 누르면 `isFavorite` 값이 바뀌고, SwiftUI가 버튼의 글자를 다시 표시 !!






# 1-3 `@State`는 언제 사용할까?

View 안에서만 필요한 간단한 값을 관리할 때 사용함

- 버튼이 눌렸는지
- 입력창에 어떤 글자가 입력됐는지
- 화면에 팝업을 보여줄지
- 선택된 탭이 무엇인지

반대로 여러 화면에서 공유하거나 복잡한 데이터 흐름을 관리해야 하는 값은 ViewModel 같은 별도의 타입으로 관리할 수 있음






# 1-4 `Binding`이란?

→ 다른 곳에서 소유한 상태를 읽고 수정할 수 있게 연결해주는 값

`@State`가 상태를 직접 소유한다면 `@Binding`은 그 상태를 전달받아 함께 사용함

```swift
struct FavoriteButton: View {
    @Binding var isFavorite: Bool

    var body: some View {
        Button(isFavorite ? "찜 해제" : "찜하기") {
            isFavorite.toggle()
        }
    }
}
```

`FavoriteButton`은 `isFavorite`의 값을 직접 소유하지 않지만 전달받은 값을 읽고 바꿀 수 있음






# 1-5 `@State`를 `Binding`으로 전달하기

`@State`를 가진 부모 View는 `$`를 붙여 자식 View에 Binding으로 전달할 수 있음

```swift
struct CharacterView: View {
    @State private var isFavorite = false

    var body: some View {
        FavoriteButton(isFavorite: $isFavorite)
    }
}
```

- `isFavorite`: 상태의 값
- `$isFavorite`: 그 상태를 수정할 수 있는 Binding

자식 View에서 값을 바꾸면 부모 View가 소유한 상태도 바뀜

```
CharacterView의 @State
↕ $isFavorite
FavoriteButton의 @Binding
```






# 1-6 입력창에서 `Binding` 사용하기

텍스트 입력창은 입력값을 읽고 수정해야 하므로 Binding을 받음

```swift
struct SearchView: View {
    @State private var keyword = ""

    var body: some View {
        TextField("치이카와 검색", text: $keyword)
    }
}
```

사용자가 검색어를 입력하면 `keyword` 상태가 바뀜  
검색어를 입력하는 동안 화면과 값이 연결되어 계속 갱신됨






# 1-7 `State`와 `Binding` 차이

| 구분 | 역할 |
|---|---|
| `@State` | View가 상태를 소유하고 관리함 |
| `@Binding` | 다른 곳에서 소유한 상태를 전달받아 함께 사용함 |

쉽게 말하면 `@State`는 내가 가진 값이고 `@Binding`은 다른 View가 가진 값을 연결해서 사용하는 것임






# 1-8 주의할 점

- `@State`는 해당 View가 소유하는 간단한 상태에 사용함
- 부모 View의 `@State`를 자식 View가 바꿔야 하면 `@Binding`으로 전달함
- `@State` 값을 일반 상수처럼 복사해 전달하면 원래 상태와 연결되지 않을 수 있음
- 상태가 바뀌면 SwiftUI가 해당 상태를 사용하는 화면을 다시 계산함






# 1-9 정리 ✨

- 상태는 버튼 선택이나 검색어처럼 화면에 영향을 주는 값임
- `@State`는 View가 직접 관리하는 상태에 사용함
- `@Binding`은 다른 View가 가진 상태를 전달받아 읽고 수정함
- `$`를 붙이면 `@State`를 Binding으로 전달할 수 있음
- 치이카와 찜 버튼처럼 여러 View가 같은 값을 바꿔야 할 때 Binding을 사용할 수 있음

> ### ⇒ `@State`는 값을 가지고 `@Binding`은 다른 곳의 값을 연결해서 함께 사용 ✨
