### Ⅱ. Actor와 MainActor




# 2-1 `Actor`란?

→ <mark>여러 비동기 작업이 같은 데이터에 동시에 접근하지 않도록 보호하는 타입

여러 작업이 같은 값을 동시에 바꾸면 예상하지 못한 결과가 생길 수 있음  
`Actor`는 한 번에 하나의 작업만 격리된 데이터에 접근하도록 조정함






# 2-2 데이터 보호가 필요한 상황

예를 들어 여러 작업이 동시에 같은 배열에 값을 추가한다고 해보자

```text
작업 A: 배열에 치이카와 추가
작업 B: 배열에 하치와레 추가
```

여러 작업이 같은 데이터를 동시에 수정하면 변경 내용이 꼬일 수 있음  
이런 문제를 막기 위해 공유 데이터를 `Actor` 안에서 관리할 수 있음






# 2-3 Actor 만들기

`actor` 키워드로 Actor를 정의함

```swift
actor CharacterStore {
    private var characters: [String] = []

    func add(_ character: String) {
        characters.append(character)
    }

    func getCharacters() -> [String] {
        characters
    }
}
```

`characters`는 `CharacterStore` 안에서 관리됨  
외부 작업은 Actor의 메서드를 통해 데이터에 접근함






# 2-4 Actor에 접근하기

Actor 바깥에서 Actor의 메서드를 호출할 때는 `await`를 사용함

```swift
let store = CharacterStore()

await store.add("치이카와")
let characters = await store.getCharacters()
```

Actor는 데이터 접근을 안전하게 조정해야 하므로 외부에서의 접근은 비동기적으로 처리됨






# 2-5 `MainActor`란?

→ UI와 관련된 작업을 메인 실행 흐름에서 처리하도록 하는 특별한 Actor

화면에 보이는 상태를 변경할 때는 메인 액터에서 처리해야 하는 경우가 많음  
`MainActor`를 사용하면 관련 작업이 메인 실행 흐름에서 이뤄지도록 지정할 수 있음






# 2-6 타입 전체에 `@MainActor` 적용하기

ViewModel 전체를 메인 액터에서 동작하도록 지정할 수 있음

```swift
@MainActor
final class CharacterViewModel {
    var characters: [String] = []

    func updateCharacters(_ newCharacters: [String]) {
        characters = newCharacters
    }
}
```

이 ViewModel의 상태와 메서드는 메인 액터에서 관리됨  
SwiftUI 화면에 연결된 값을 바꿀 때 사용할 수 있음






# 2-7 `MainActor.run`으로 실행하기

필요한 코드 블록만 메인 액터에서 실행하고 싶다면 `MainActor.run`을 사용할 수 있음

```swift
await MainActor.run {
    viewModel.characters = ["치이카와", "하치와레"]
}
```

예를 들어 비동기 요청 결과를 받은 다음 화면 상태를 갱신할 때 활용할 수 있음






# 2-8 `Actor`와 `MainActor` 비교

- `Actor`: 공유 데이터를 안전하게 보호하기 위해 사용함
- `MainActor`: UI와 연결된 작업을 메인 실행 흐름에서 처리하기 위해 사용함

둘 다 동시성 환경에서 작업을 안전하게 관리하는 역할을 하지만 주로 보호하는 대상이 다름






# 2-9 주의할 점

- Actor가 모든 동시성 문제를 자동으로 해결하는 것은 아님
- Actor 외부에서 데이터를 읽거나 바꿀 때는 비동기 접근이 필요할 수 있음
- `MainActor`는 네트워크 요청을 빠르게 만드는 기능이 아님
- UI와 관련된 값은 메인 액터에서 갱신하도록 관리해야 함
- 타입이나 함수에 어디까지 `@MainActor`를 붙일지는 역할에 맞게 정해야됨






# 2-10 정리 ✨

* `Actor`는 여러 작업이 공유 데이터를 동시에 바꾸지 않도록 보호함
* Actor 외부에서 메서드를 호출할 때는 보통 `await`를 사용
* `MainActor`는 UI 작업을 메인 실행 흐름에서 처리하도록 함
* ViewModel 전체나 필요한 코드에 `@MainActor`를 적용 가능
* `Actor`는 공유 데이터 보호에, `MainActor`는 UI 작업 관리에 주로 사용

> ### ⇒ `Actor`는 공유 데이터를 보호하고, `MainActor`는 화면과 연결된 작업을 안전하게 처리 ✨
