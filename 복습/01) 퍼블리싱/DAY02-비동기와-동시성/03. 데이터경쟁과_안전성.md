### Ⅲ. 데이터 경쟁과 안전성


<br>

# 3-1 데이터 경쟁이란?

→ 여러 작업이 같은 데이터에 동시에 접근하면서 값이 예상과 다르게 바뀌는 문제

예를 들어 여러 작업이 치이카와 목록을 동시에 수정하면 어떤 변경이 먼저 반영될지 예상하기 어려울 수 있음

```text
작업 A: 치이카와 추가
작업 B: 하치와레 추가
```
<u>↳ 두 작업이 같은 배열을 동시에 수정</u>


이런 문제를 **데이터 경쟁(Data Race)** 이라고 함


<br>
<br>



# 3-2 데이터 경쟁이 생기는 경우

여러 작업이 같은 데이터를 동시에 읽거나 수정할 때 문제가 생길 수 있음

```swift
var characters: [String] = []

Task {
    characters.append("치이카와")
}

Task {
    characters.append("하치와레")
}
```

각 작업이 같은 배열에 동시에 접근하므로 데이터가 안전하게 관리되지 않을 수 있음


<br>
<br>



# 3-3 데이터 경쟁이 위험한 이유

데이터 경쟁이 생기면 다음과 같은 문제가 발생할 수 있음

- 일부 변경 내용이 사라질 수 있음
- 데이터가 예상과 다른 순서로 바뀔 수 있음
- 오류가 상황에 따라 다르게 나타날 수 있음
- 문제가 생긴 시점을 찾기 어려울 수 있음

같은 코드를 실행해도 작업이 진행되는 순서에 따라 결과가 달라질 수 있음


<br>
<br>



# 3-4 공유 데이터 보호하기

여러 작업이 함께 사용하는 데이터는 한곳에서 안전하게 관리하는 것이 좋음  
Swift에서는 `Actor`를 사용해 공유 데이터를 보호할 수 있음

```swift
actor CharacterStore {
    private var characters: [String] = []

    func add(_ character: String) {
        characters.append(character)
    }

    func getCharacters() -> [String] {
        characters
    }
}
```

배열을 직접 공유하는 대신 Actor의 메서드를 통해 데이터를 읽고 수정함



<br>
<br>


# 3-5 `await`가 필요한 이유

Actor 바깥에서 Actor의 메서드에 접근할 때는 `await`를 사용함

```swift
let store = CharacterStore()

await store.add("치이카와")
let characters = await store.getCharacters()
```

Actor가 데이터를 안전하게 다룰 수 있도록 접근 순서를 조정하기 때문에 호출자는 결과를 비동기적으로 기다려야 함



<br>
<br>


# 3-6 UI 상태 안전하게 바꾸기

화면에 표시되는 상태는 `MainActor`에서 관리할 수 있음

```swift
@MainActor
final class CharacterViewModel {
    private(set) var characters: [String] = []

    func updateCharacters(_ newCharacters: [String]) {
        characters = newCharacters
    }
}
```

ViewModel을 `@MainActor`로 지정하면 화면과 연결된 데이터 변경을 메인 액터에서 관리할 수 있음



<br>
<br>


# 3-7 오래된 네트워크 응답 주의하기

검색을 빠르게 바꾸면 이전 검색 요청과 최신 검색 요청이 함께 진행될 수 있음


> "치이" 검색 요청 → "치이카와" 검색 요청 → 최신 요청 결과가 먼저 도착 → 이전 요청 결과가 나중에 도착

이전 요청 결과가 늦게 도착해 화면을 덮으면 현재 검색어와 맞지 않는 결과가 표시될 수 있음  
필요하면 이전 작업을 취소하거나 결과를 반영하기 전에 현재 요청인지 확인해야 함


<br>
<br>



# 3-8 데이터 안전하게 다루는 방법

- 같은 데이터를 여러 작업에서 직접 수정하지 않기
- 공유 데이터는 Actor 안에서 관리하기
- UI와 연결된 상태는 메인 액터에서 갱신하기
- 필요 없는 비동기 작업은 취소하기
- 취소되었거나 오래된 요청의 결과가 화면에 반영되지 않는지 확인하기




<br>
<br>

# 3-9 정리

* 데이터 경쟁은 여러 작업이 같은 데이터에 동시에 접근할 때 생길 가능성 있음
* 작업 순서에 따라 결과가 달라지거나 일부 변경이 누락될 수 있음
* `Actor`는 공유 데이터를 안전하게 관리하는 데 사용
* `MainActor`는 화면과 연결된 상태를 메인 실행 흐름에서 관리
* 검색 요청처럼 오래 걸리는 작업은 오래된 결과가 화면을 덮지 않도록 확인해야 함

<br>

> ### ⇒ 공유 데이터는 안전하게 관리하고 화면 상태는 MainActor에서 바꿔야 데이터 경쟁을 줄일 수 있음 ✨
