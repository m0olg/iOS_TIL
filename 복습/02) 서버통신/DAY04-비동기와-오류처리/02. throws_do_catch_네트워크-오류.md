### Ⅱ. `throws`, `do-catch`, 네트워크 오류




# 2-1 오류 처리가 필요한 이유

네트워크 요청은 여러 이유로 실패할 수 있음

- 인터넷 연결이 끊긴 경우
- 요청 주소가 잘못된 경우
- 서버가 응답하지 않는 경우
- 서버가 오류 상태 코드를 돌려준 경우
- 응답 데이터를 예상한 형태로 읽을 수 없는 경우

오류가 발생했을 때 앱이 갑자기 멈추지 않도록 적절히 처리해야 함






# 2-2 `throws`란?

→ 함수 안에서 발생한 오류를 호출한 곳으로 전달할 수 있음을 나타내는 키워드

```swift
func fetchData() throws {
    // 오류가 발생할 수 있는 작업
}
```

`throws`가 붙은 함수는 실행 중 오류를 던질 수 있음  
이 함수를 호출할 때는 오류 처리 방법을 함께 정해야 함






# 2-3 `try`로 오류가 발생할 수 있는 함수 호출하기

`throws`가 붙은 함수는 `try`와 함께 호출함

```swift
try fetchData()
```

네트워크 요청도 실패할 수 있으므로 `try`를 사용함

```swift
let (data, response) = try await URLSession.shared.data(from: url)
```

- `try`: 오류가 발생할 수 있는 코드를 실행함
- `await`: 비동기 작업의 결과를 기다림

오류가 발생하면 호출한 곳으로 전달되므로, 오류를 처리하는 코드가 필요함






# 2-4 `do-catch`란?

→ 오류가 발생할 수 있는 코드를 실행하고, 오류가 나면 처리하는 구문

```swift
do {
    try fetchData()
} catch {
    print("오류 발생:", error)
}
```

- `do`: 오류가 발생할 수 있는 코드를 작성
- `catch`: 오류가 발생했을 때 처리

`do-catch` 안에서 오류를 처리하면 앱이 갑자기 종료되는 것을 막고, 오류 안내나 재시도 같은 동작을 할 수 있음






# 2-5 네트워크 요청에 `do-catch` 사용하기

```swift
do {
    let (data, response) = try await URLSession.shared.data(from: url)
    print("응답 데이터:", data)
    print("응답 정보:", response)
} catch {
    print("네트워크 요청 실패:", error)
}
```

- 요청에 성공하면 `do` 안의 코드가 이어서 실행됨
- 요청 중 오류가 발생하면 `catch` 블록이 실행됨






# 2-6 `error`로 오류 확인하기

`catch` 안의 `error`에는 발생한 오류 정보가 들어 있음

```swift
do {
    try fetchData()
} catch {
    print("오류 발생:", error)
}
```

개발 중에는 오류 내용을 출력해 원인을 확인할 수 있음  
사용자에게 오류를 보여줄 때는 이해하기 쉬운 안내 문구를 사용하는 것이 좋음

```swift
catch {
    print("서버에 연결할 수 없어요. 인터넷 연결을 확인해주세요.")
}
```






# 2-7 네트워크 오류와 HTTP 상태 코드 오류

네트워크 요청 자체가 실패한 경우와, 서버에서 오류 상태 코드를 받은 경우는 다름

### 네트워크 요청 자체가 실패한 경우

인터넷 연결 문제나 잘못된 주소 등으로 응답을 받지 못할 수 있음  
이런 오류는 `catch`에서 처리함

### 서버 응답을 받았지만 상태 코드가 성공이 아닌 경우

서버가 `404`, `500` 같은 상태 코드를 응답할 수 있음  
이 경우 응답은 받은 것이므로 `HTTPURLResponse`의 `statusCode`를 확인해야 함






# 2-8 상태 코드도 함께 확인하기

`URLSession` 요청에서 오류가 발생하지 않았더라도 서버가 요청을 성공적으로 처리했다는 뜻은 아님

```swift
guard let httpResponse = response as? HTTPURLResponse else {
    print("HTTP 응답을 확인할 수 없음")
    return
}

guard (200...299).contains(httpResponse.statusCode) else {
    print("서버 응답 오류:", httpResponse.statusCode)
    return
}
```

보통 `200`부터 `299`까지의 상태 코드를 성공 응답으로 처리함  
다만 API에 따라 성공 여부와 응답 내용이 다를 수 있으므로 API 문서도 확인해야 함






# 2-9 `throws`로 오류 전달하기

함수 안에서 직접 오류를 처리하지 않고, 호출한 곳에서 처리하도록 전달할 수도 있음

```swift
func fetchData() async throws -> Data {
    let (data, _) = try await URLSession.shared.data(from: url)
    return data
}
```

이 함수를 호출하는 쪽에서 `try`와 `do-catch`를 사용함

```swift
do {
    let data = try await fetchData()
    print("받은 데이터:", data)
} catch {
    print("데이터 요청 실패:", error)
}
```

오류를 함수 안에서 처리할지, 호출한 곳으로 전달할지는 코드의 역할에 따라 정할 수 있음






# 2-10 전체 예시

```swift
func fetchData(from url: URL) async throws -> Data {
    let (data, response) = try await URLSession.shared.data(from: url)

    guard let httpResponse = response as? HTTPURLResponse else {
        throw URLError(.badServerResponse)
    }

    guard (200...299).contains(httpResponse.statusCode) else {
        throw URLError(.badServerResponse)
    }

    return data
}

do {
    let data = try await fetchData(from: url)
    print("요청 성공:", data)
} catch {
    print("요청 실패:", error)
}
```

이 코드에서는 다음 순서로 동작함

1. `fetchData`가 비동기 작업을 수행하므로 `async`를 붙임
2. 오류를 호출한 곳으로 전달하므로 `throws`를 붙임
3. 서버에 요청할 때 `try await`를 사용함
4. 응답이 성공 범위인지 확인함
5. 성공하면 응답 데이터 `Data`를 반환함
6. 오류가 발생하면 호출한 곳의 `catch`에서 처리함






# 정리

* `throws`는 함수에서 오류가 발생할 수 있음을 나타냄
* `try`는 오류가 발생할 수 있는 함수를 호출할 때 사용함
* `do-catch`는 오류를 처리하는 구문임
* 네트워크 요청 자체가 실패하면 `catch`에서 확인함
* 서버 응답을 받았더라도 상태 코드가 실패일 수 있어 따로 확인해야 함
* 오류를 함수 안에서 처리하거나 호출한 곳으로 전달할 수 있음

> ### ⇒ 네트워크 요청은 `do-catch`로 오류를 처리하고, 응답 상태 코드도 따로 확인해야 함 ✨
