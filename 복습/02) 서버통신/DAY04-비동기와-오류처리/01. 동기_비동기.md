### I. 동기·비동기·async-await




# 1-1 동기란?

→ 한 작업이 끝날 때까지 기다린 뒤 다음 작업을 진행하는 방식

```text
작업 A 시작
→ 작업 A 완료
→ 작업 B 시작
```

앞 작업이 끝나야 다음 작업을 시작할 수 있음

예를 들어 카페에서 음료를 주문한 뒤, 음료가 나올 때까지 기다렸다가 다음 일을 하는 상황과 비슷함






# 1-2 비동기란?

→ 한 작업이 끝나기를 기다리는 동안 다른 작업을 진행할 수 있는 방식

```text
작업 A 시작
→ 작업 A가 진행되는 동안 작업 B 진행
→ 작업 A 완료
```

네트워크 요청처럼 시간이 얼마나 걸릴지 모르는 작업을 처리할 때 비동기 방식을 사용함

예를 들어 서버에 데이터를 요청해둔 뒤, 응답을 기다리는 동안 앱 화면이 멈추지 않고 다른 작업을 할 수 있음






# 1-3 동기와 비동기 비교

### 동기

```text
작업 A 시작
→ 작업 A 완료
→ 작업 B 시작
```

- 작업 순서를 예상하기 쉬움
- 앞 작업이 오래 걸리면 뒤 작업도 기다려야 함

### 비동기

```text
작업 A 시작
→ 다른 작업 진행
→ 작업 A 완료 후 결과 처리
```

- 오래 걸리는 작업을 기다리는 동안 다른 일을 할 수 있음
- 결과가 언제 도착할지 알 수 없어, 결과를 처리하는 방법이 필요함






# 1-4 네트워크 요청을 비동기로 처리하는 이유

서버에 요청을 보내면 인터넷 상태나 서버 상황에 따라 응답이 늦어질 수 있음

요청이 끝날 때까지 앱 화면을 멈춰 기다리게 하면 사용하기 불편해짐  
그래서 네트워크 요청은 보통 비동기로 처리함

```text
앱이 서버에 요청
→ 요청이 진행되는 동안 화면은 계속 동작
→ 응답이 도착하면 결과 처리
```






# 1-5 async와 await란?

Swift에서는 `async`와 `await`를 사용해 비동기 작업을 작성할 수 있음

- `async`: 함수가 비동기 작업을 수행함을 표시
- `await`: 비동기 작업의 결과를 기다림

```swift
func fetchCharacter() async {
    let (data, response) = await URLSession.shared.data(from: url)
}
```

`await`가 있어도 앱 전체가 멈추는 것은 아님  
해당 비동기 작업의 결과를 기다리는 동안 다른 작업이 진행될 수 있음






# 1-6 async 함수 호출하기

`async` 함수는 다른 비동기 코드 안에서 `await`와 함께 호출함

```swift
func loadData() async {
    await fetchCharacter()
}
```

함수 안에서 `await`를 사용하면 비동기 작업의 결과를 기다린 뒤 다음 코드를 실행함

```swift
func loadData() async {
    print("요청 시작")
    await fetchCharacter()
    print("요청 완료")
}
```

위 코드에서는 `fetchCharacter()`의 작업이 끝난 뒤 `"요청 완료"`가 출력됨






# 1-7 URLSession에서 async-await 사용하기

`URLSession`의 데이터 요청 메서드는 비동기 방식으로 동작함

```swift
func fetchCharacters() async throws {
    let (data, response) = try await URLSession.shared.data(from: url)
    print(data)
    print(response)
}
```

- `try`: 오류가 발생할 수 있는 작업을 호출
- `await`: 비동기 작업의 결과를 기다림
- `throws`: 함수 안에서 발생한 오류를 호출한 곳으로 전달할 수 있음을 표시






# 1-8 async 함수 호출 예시

비동기 함수는 호출하는 쪽에서도 비동기 작업을 시작해야 함

```swift
Task {
    await fetchCharacters()
}
```

`Task`는 비동기 작업을 시작할 때 사용할 수 있음  
`Task`와 UI 갱신은 `03. Task-MainActor-UI갱신.md`에서 정리함






# 1-9 정리

* 동기는 앞 작업이 끝난 뒤 다음 작업을 진행하는 방식
* 비동기는 작업을 기다리는 동안 다른 일을 진행할 수 있는 방식
* 네트워크 요청은 응답 시간이 일정하지 않으므로 보통 비동기로 처리함
* `async`는 함수가 비동기 작업을 수행함을 나타냄
* `await`는 비동기 작업의 결과를 기다림
* 비동기 작업에서 오류가 발생할 수 있으면 `throws`와 `try`를 함께 사용할 수 있음

> ### ⇒ `async`로 비동기 함수를 표시하고, `await`로 그 결과를 기다림 ✨
