### Ⅱ. 에러 타입과 응답 처리




# 2-1 에러 타입이란?

→ 프로그램에서 발생할 수 있는 오류를 종류별로 표현한 것

네트워크 요청에서는 URL 오류, 서버 응답 오류, JSON 디코딩 오류처럼 여러 문제가 생길 수 있음  
오류를 종류별로 나누면 원인을 확인하고 상황에 맞게 처리하기 쉬움






# 2-2 네트워크 오류를 나누는 이유

모든 오류를 똑같이 처리하면 사용자에게 상황을 제대로 안내하기 어려움

- 인터넷 연결 문제 → 연결 상태 확인 안내
- 서버 오류 응답 → 잠시 후 다시 시도 안내
- JSON 디코딩 실패 → 응답 형식이나 모델 확인
- 잘못된 URL → 요청 주소 확인

오류마다 원인과 처리 방법이 다를 수 있으므로 구분해서 관리하는 것이 좋음






# 2-3 직접 에러 타입 만들기

Swift에서는 `Error`를 채택해 프로젝트에 필요한 오류 타입을 만들 수 있음

```swift
enum NetworkError: Error {
    case invalidURL
    case invalidResponse
    case serverError(statusCode: Int)
    case decodingError
}
```

- `invalidURL`: URL을 만들 수 없음
- `invalidResponse`: 예상한 HTTP 응답이 아님
- `serverError(statusCode:)`: 서버가 성공 범위가 아닌 상태 코드를 보냄
- `decodingError`: 응답 데이터를 모델로 변환하지 못함






# 2-4 에러를 던지기

오류가 발생했을 때 `throw`를 사용해 에러를 던질 수 있음

```swift
guard let url = URL(string: address) else {
    throw NetworkError.invalidURL
}
```

에러를 던진 함수는 `throws`를 표시해야 함

```swift
func makeURL(from address: String) throws -> URL {
    guard let url = URL(string: address) else {
        throw NetworkError.invalidURL
    }

    return url
}
```

에러는 함수를 호출한 곳으로 전달되며, 호출한 쪽에서 처리할 수 있음






# 2-5 HTTP 상태 코드에 따라 에러 처리하기

응답을 받았지만 상태 코드가 성공 범위가 아닐 수도 있음  
상태 코드를 포함해 에러를 정의하면 서버 응답 문제를 더 구체적으로 알 수 있음

```swift
enum NetworkError: Error {
    case invalidResponse
    case serverError(statusCode: Int)
}
```

```swift
guard let httpResponse = response as? HTTPURLResponse else {
    throw NetworkError.invalidResponse
}

guard (200...299).contains(httpResponse.statusCode) else {
    throw NetworkError.serverError(
        statusCode: httpResponse.statusCode
    )
}
```

이렇게 하면 어떤 상태 코드에서 오류가 났는지 확인할 수 있음






# 2-6 `do-catch`에서 에러 종류별 처리하기

`catch`에서 에러 종류에 따라 다르게 처리할 수 있음

```swift
do {
    let data = try await fetchData()
    print(data)
} catch NetworkError.invalidURL {
    print("요청 주소를 확인해주세요.")
} catch NetworkError.serverError(let statusCode) {
    print("서버 응답 오류 :", statusCode)
} catch {

}
```

- 특정 오류를 먼저 처리할 수 있음
- 마지막 `catch`는 위에서 따로 처리하지 않은 오류를 처리함






# 2-7 응답 모델과 응답 처리

서버 응답은 JSON `Data`로 받을 수 있고, 앱에서 사용하려면 Swift 모델로 디코딩해야 함

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}
```

`JSONDecoder`로 응답 데이터를 모델로 변환함

```swift
let character = try JSONDecoder().decode(
    Character.self,
    from: data
)
```

서버가 보내는 JSON 구조와 모델의 키·자료형이 맞지 않으면 디코딩 오류가 발생할 수 있음






# 2-8 오류를 포함한 응답 처리 예시

```swift
func decodeCharacter(from data: Data) throws -> Character {
    do {
        return try JSONDecoder().decode(Character.self, from: data)
    } catch {
        throw NetworkError.decodingError
    }
}
```

디코딩 오류를 앱에서 정의한 `NetworkError.decodingError`로 바꿔 전달하는 예시임 !! \
다만 오류의 구체적인 원인을 확인하고 싶다면 원래 오류 정보를 보존하는 방식으로 설계할 수도 있음






# 2-9 전체 흐름 예시와 정리

```swift
enum NetworkError: Error {
    case invalidURL
    case invalidResponse
    case serverError(statusCode: Int)
    case decodingError
}

func fetchCharacter(from address: String) async throws -> Character {
    guard let url = URL(string: address) else {
        throw NetworkError.invalidURL
    }

    let (data, response) = try await URLSession.shared.data(from: url)

    guard let httpResponse = response as? HTTPURLResponse else {
        throw NetworkError.invalidResponse
    }

    guard (200...299).contains(httpResponse.statusCode) else {
        throw NetworkError.serverError(
            statusCode: httpResponse.statusCode
        )
    }

    do {
        return try JSONDecoder().decode(Character.self, from: data)
    } catch {
        throw NetworkError.decodingError
    }
}
```

* 에러 타입을 만들면 오류의 종류를 구분할 수 있음
* `throw`로 오류를 전달하고, 호출한 곳에서 `do-catch`로 처리
* HTTP 상태 코드가 성공 범위가 아니면 상태 코드 오류로 처리할 수 있음
* JSON 디코딩 실패도 별도 오류로 구분할 수 있음
* 실제 요청과 응답 형식은 API 문서에 맞춰야 함

> ### ⇒ 오류를 종류별로 정의하고, 응답 상태와 디코딩 결과를 확인해 상황에 맞게 처리 ✨
