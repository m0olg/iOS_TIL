### Ⅲ. 프로토콜과 의존성 주입




# 3-1 프로토콜이란?

→ 타입이 갖춰야 할 프로퍼티와 메서드의 규칙을 정의한 것

프로토콜은 기능의 구체적인 구현보다 **어떤 기능이 있어야 하는지**를 먼저 정함

```swift
protocol CharacterService {
    func fetchCharacter() async throws -> Character
}
```

이 프로토콜을 따르는 타입은 `fetchCharacter()` 기능을 구현해야 함






# 3-2 프로토콜을 사용하는 이유

화면이나 뷰 모델이 특정 네트워크 구현에 직접 의존하면 테스트하거나 구현 방식을 바꾸기 어려워질 수 있음

프로토콜을 기준으로 코드를 작성하면 실제 서버 통신과 테스트용 구현을 같은 규칙으로 사용할 수 있음

```text
화면 또는 뷰 모델
        ↓
CharacterService 프로토콜
        ↑
실제 네트워크 서비스 / 테스트용 서비스
```






# 3-3 프로토콜 채택하기

타입 이름 뒤에 프로토콜을 적고 필요한 기능을 구현함

```swift
protocol CharacterService {
    func fetchCharacter() async throws -> Character
}

final class APIClient: CharacterService {
    func fetchCharacter() async throws -> Character {
        // 실제 서버 요청
        fatalError("요청 코드 작성")
    }
}
```

`APIClient`가 `CharacterService`를 채택했으므로 프로토콜에 선언된 메서드를 구현해야 함






# 3-4 의존성이란?

→ 어떤 타입이 다른 타입의 기능을 사용하는 관계

예를 들어 뷰 모델이 `APIClient`를 직접 만들어 사용하면, 뷰 모델은 `APIClient` 구현에 의존하게 됨

```swift
final class CharacterViewModel {
    private let client = APIClient()
}
```

이 경우 테스트할 때 실제 서버 요청을 보내지 않고 다른 구현으로 바꾸기 어려울 수 있음






# 3-5 의존성 주입이란?

→ 필요한 객체를 타입 내부에서 직접 만들지 않고, 외부에서 전달받는 방식

```swift
final class CharacterViewModel {
    private let service: CharacterService

    init(service: CharacterService) {
        self.service = service
    }
}
```

`CharacterViewModel`은 사용할 서비스를 직접 만들지 않고 초기화할 때 전달받음  
이처럼 필요한 의존성을 외부에서 전달하는 것을 **의존성 주입**이라고 함






# 3-6 실제 APIClient 전달하기

실제 앱에서는 `APIClient`를 만들어 뷰 모델에 전달할 수 있음

```swift
let service = APIClient()
let viewModel = CharacterViewModel(service: service)
```

`APIClient`가 `CharacterService`를 채택했기 때문에, `CharacterService`를 받는 자리에 전달할 수 있음

```text
APIClient
→ CharacterService 규칙을 따름
→ CharacterViewModel에 전달
```






# 3-7 테스트용 서비스 만들기

프로토콜을 이용하면 실제 서버에 요청하지 않는 테스트용 구현을 만들 수 있음

```swift
final class MockCharacterService: CharacterService {
    func fetchCharacter() async throws -> Character {
        Character(id: 1, name: "치이카와")
    }
}
```

테스트할 때는 `APIClient` 대신 `MockCharacterService`를 전달할 수 있음

```swift
let mockService = MockCharacterService()
let viewModel = CharacterViewModel(service: mockService)
```

서버 연결 없이도 뷰 모델이 데이터를 잘 처리하는지 확인할 수 있음






# 3-8 의존성 주입의 장점

- 실제 구현과 테스트용 구현을 쉽게 바꿀 수 있음
- 뷰 모델이 네트워크 구현에 직접 묶이지 않음
- 각 타입의 역할을 분리하기 쉬움
- 서버 요청 없이도 테스트할 수 있음
- 코드 변경이나 확장에 유연하게 대응할 수 있음






# 3-9 프로토콜과 의존성 주입 함께 사용하기

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}

protocol CharacterService {
    func fetchCharacter() async throws -> Character
}

final class CharacterViewModel {
    private let service: CharacterService

    init(service: CharacterService) {
        self.service = service
    }

    func loadCharacter() async throws -> Character {
        try await service.fetchCharacter()
    }
}
```

뷰 모델은 `CharacterService`라는 규칙만 알고 있음  
실제로 서버에 요청하는지, 테스트용 데이터를 돌려주는지는 전달받은 객체가 결정함






# 3-10 의존성 주입 방식

의존성을 전달하는 방법은 여러 가지가 있지만, 초기화할 때 전달하는 방식이 자주 사용됨

```swift
init(service: CharacterService) {
    self.service = service
}
```

이 방식은 객체를 만들 때 필요한 의존성이 무엇인지 드러나고, 의존성이 빠진 상태로 객체가 만들어지는 것을 막기 쉬움

프로젝트 구조에 따라 프로퍼티로 전달하거나 별도의 의존성 관리 도구를 사용할 수도 있음






# 3-11 정리

* 프로토콜은 타입이 따라야 할 기능의 규칙을 정의함
* 프로토콜을 사용하면 실제 네트워크 구현과 테스트용 구현을 같은 방식으로 다룰 수 있음
* 의존성은 한 타입이 다른 타입의 기능을 사용하는 관계임
* 의존성 주입은 필요한 객체를 외부에서 전달받는 방식임
* 프로토콜과 의존성 주입을 함께 사용하면 구현을 바꾸거나 테스트하기 쉬워짐
* 뷰 모델은 구체적인 `APIClient`보다 서비스 프로토콜에 의존하도록 구성할 수 있음

> ### ⇒ 프로토콜로 사용 규칙을 정하고, 필요한 구현은 외부에서 주입해 유연하게 구성함 ✨
