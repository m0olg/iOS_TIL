### Ⅰ. MVC와 MVVM 복습

<br>


# 1-1 MVC란?

→ 화면과 데이터를 역할에 따라 나누는 앱 구조

MVC는 다음 세 가지 역할로 구성됨 !!

- **Model**: 데이터와 데이터 처리
- **View**: 사용자에게 보이는 화면
- **Controller**: Model과 View를 연결하고 동작을 제어

> 사용자 입력 → Controller → Model 변경 또는 데이터 요청 → Controller가 View 갱신


<br>
<br>



# 1-2 MVC의 각 역할

### 1) Model

앱에서 사용하는 데이터와 관련된 기능을 담당함

예를 들어 캐릭터 정보를 나타내는 타입이 Model이 될 수 있음

```swift
struct Character {
    let name: String
}
```

### 2) View

사용자에게 실제로 보이는 화면을 담당함

예를 들어 이름을 보여주는 라벨이나 버튼, 목록 등이 View에 해당함

### 3) Controller

사용자 입력을 받아 Model이나 View를 연결함

예를 들어 버튼을 눌렀을 때 데이터를 불러오고 그 결과를 화면에 표시하도록 조정함


<br>
<br>



# 1-3 MVC의 장점과 주의점

역할을 나누면 코드의 목적을 이해하기 쉬워짐  
하지만 Controller가 여러 역할을 모두 맡으면 코드가 너무 커질 수 있음

Controller가 다음 일을 모두 처리하는 상황을 생각해볼 수 있음

- 버튼 입력 처리
- 네트워크 요청
- 응답 데이터 변환
- 화면 상태 관리
- 화면 갱신

이처럼 Controller에 코드가 몰리는 문제를 흔히 **Massive View Controller**라고 부름


<br>
<br>



# 1-4 MVVM이란?

→ Model, View, ViewModel로 역할을 나누는 구조

- **Model**: 앱에서 사용하는 데이터와 데이터 처리
- **View**: 사용자에게 보이는 화면
- **ViewModel**: 화면에 필요한 데이터를 준비하고 화면 상태를 관리

```
View
↕ 데이터와 사용자 동작
ViewModel
↕ 데이터 요청 및 처리
Model 또는 서비스
```

MVVM은 화면을 그리는 코드와 화면에 필요한 데이터를 준비하는 코드를 나누는 데 도움을 줌

<br>
<br>




# 1-5 ViewModel의 역할

ViewModel은 View에 보여줄 데이터를 준비하고, 사용자의 동작에 따라 필요한 처리를 수행함

예를 들어 캐릭터 정보를 보여주는 화면이라면 다음과 같은 일을 맡을 수 있음

- 서버에 캐릭터 정보 요청
- 응답 데이터를 화면에서 쓰기 좋은 형태로 준비
- 로딩 중인지, 결과가 있는지, 오류가 났는지 관리
- View에서 호출할 함수 제공

> ViewModel은 보통 화면의 UI 요소를 직접 그리기보다 화면이 사용할 데이터와 상태를 관리함


<br>
<br>



# 1-6 MVC와 MVVM 비교

### MVC

```
View ↔ Controller ↔ Model
```

Controller가 사용자 동작을 받고 View와 Model을 연결

### MVVM

```
View ↔ ViewModel ↔ Model 또는 서비스
```

ViewModel이 화면에 필요한 데이터와 상태를 관리함  
View는 ViewModel의 데이터를 바탕으로 화면을 표시함

두 구조 모두 역할을 나누기 위한 설계 방식이며 프로젝트에 따라 구체적인 구현은 달라질 수 있따

<br>
<br>




# 1-7 네트워크 요청을 MVVM으로 나누기

캐릭터 목록을 서버에서 불러오는 경우 각 역할을 다음처럼 나눌 수 있음

### 1) Model

서버 응답을 담을 데이터 타입

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}
```

### 2) ViewModel

목록을 요청하고 화면에 보여줄 데이터를 관리

```swift
@MainActor
final class CharacterViewModel {
    var characters: [Character] = []
}
```

### 3) View

ViewModel의 데이터를 화면에 표시하고 사용자 입력을 전달 !

<br>
<br>




# 1-8 정리

* MVC는 Model, View, Controller로 역할을 나누는 구조
* Controller는 사용자 동작을 처리하고 Model과 View를 연결함
* Controller에 너무 많은 역할이 모이면 코드가 복잡해질 수 있음
* MVVM은 Model, View, ViewModel로 역할을 나눔
* ViewModel은 화면에 필요한 데이터와 상태를 관리함
* MVC와 MVVM은 역할을 나누는 설계 방식이며 프로젝트에 따라 구현이 달라질 수 있음

<br>

> ### ⇒ MVVM에서는 ViewModel이 화면에 필요한 데이터와 상태를 맡아 View와 데이터 처리를 나눔 ✨
