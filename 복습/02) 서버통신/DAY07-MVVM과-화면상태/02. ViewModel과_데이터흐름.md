### Ⅱ. ViewModel과 데이터 흐름

<br>


# 2-1 ViewModel이란?

→ 화면에 필요한 데이터를 준비하고 화면 상태를 관리하는 타입

ViewModel은 화면이 직접 처리하기 복잡한 데이터 요청이나 변환을 맡을 수 있음

```text
View
↕
ViewModel
↕
APIClient 또는 Model
```

View는 사용자 입력을 ViewModel에 전달하고 ViewModel은 처리한 결과를 화면에 보여줄 데이터로 제공함


<br>
<br>



# 2-2 ViewModel을 사용하는 이유

화면 코드에서 네트워크 요청과 응답 처리를 모두 하면 View의 역할이 너무 많아질 수 있음

ViewModel을 두면 다음처럼 역할을 나눌 수 있음

### 1) View

- 화면 표시
- 버튼이나 입력 등 사용자 동작 전달
- ViewModel의 상태에 따라 화면 갱신

### 2) ViewModel

- 데이터 요청
- 응답 처리
- 화면에 필요한 데이터 관리
- 로딩과 오류 상태 관리

<br>
<br>




# 2-3 데이터 흐름

ViewModel을 사용하는 화면에서는 보통 다음과 같은 순서로 데이터가 흐름

```text
사용자 동작
→ View가 ViewModel에 전달
→ ViewModel이 데이터 요청
→ 응답을 처리해 상태 갱신
→ View가 바뀐 상태를 화면에 표시
```

예를 들어 새로고침 버튼을 누르면 View가 ViewModel에 데이터를 다시 불러오도록 요청함  
ViewModel은 서버에서 데이터를 받아 화면에 표시할 상태를 갱신


<br>
<br>



# 2-4 ViewModel에서 데이터 요청하기

ViewModel은 `APIClient` 같은 네트워크 타입을 이용해 데이터를 가져올 수 있음

```swift
@MainActor
final class CharacterViewModel {
    private let client = APIClient()
    private(set) var characters: [Character] = []

    func loadCharacters() async {
        do {
            characters = try await client.fetchCharacters()
        } catch {
            print("캐릭터 정보를 불러오지 못했어요:", error)
        }
    }
}
```

- `loadCharacters()`: 목록을 불러오는 함수
- `client`: 서버 요청을 담당하는 객체
- `characters`: 화면에 보여줄 캐릭터 목록
- `private(set)`: ViewModel 내부에서 값을 바꾸고 외부에서는 읽을 수 있게 함



<br>
<br>


# 2-5 View에서 ViewModel 사용하기

View는 ViewModel의 함수를 호출해 필요한 동작을 전달함

```swift
Task {
    await viewModel.loadCharacters()
}
```

네트워크 요청은 비동기 작업이므로 `await`를 사용함  
SwiftUI나 UIKit 등 사용하는 UI 방식에 따라 ViewModel을 연결하는 구체적인 방법은 달라질 수 있음


<br>
<br>



# 2-6 화면에 보여줄 데이터 준비하기

서버 응답 모델을 그대로 사용하거나 화면에서 쓰기 좋은 형태로 가공할 수 있음

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}
```

ViewModel은 받은 데이터를 `characters`에 저장함

```swift
characters = response
```

View는 이 데이터를 읽어 목록이나 상세 정보로 표시함



<br>
<br>


# 2-7 ViewModel에서 화면 상태 관리하기

화면에는 데이터뿐 아니라 현재 상황을 나타내는 상태도 필요함

예를 들어 다음 상태를 관리할 수 있음

- 데이터를 불러오는 중
- 데이터를 불러와 표시할 수 있음
- 데이터가 비어 있음
- 요청이 실패함

상태를 따로 관리하면 View가 상황에 맞는 화면을 표시하기 쉬워짐

<br>
<br>




# 2-8 ViewModel을 테스트하기 쉬운 구조

ViewModel이 구체적인 네트워크 객체를 직접 만들면 테스트할 때 실제 서버 요청이 필요할 수 있음

프로토콜을 통해 네트워크 기능을 전달받으면 실제 APIClient 대신 테스트용 객체를 넣을 수 있음

```swift
protocol CharacterService {
    func fetchCharacters() async throws -> [Character]
}

@MainActor
final class CharacterViewModel {
    private let service: CharacterService

    init(service: CharacterService) {
        self.service = service
    }
}
```

이 방식은 테스트 코드에서 원하는 데이터를 돌려주는 서비스로 바꿔 사용할 수 있음


<br>
<br>



# 2-9 정리

* ViewModel은 화면에 필요한 데이터와 상태를 관리함
* View는 사용자 동작을 ViewModel에 전달
* ViewModel은 서버에서 받은 데이터를 화면에 맞게 준비함
* 화면은 ViewModel의 데이터와 상태를 바탕으로 갱신
* 네트워크 기능을 전달받도록 구성하면 테스트하기 쉬워질 수 있음

<br>

> ### ⇒ View는 화면을 보여주고 ViewModel은 화면에 필요한 데이터 흐름과 상태를 관리함 ✨
