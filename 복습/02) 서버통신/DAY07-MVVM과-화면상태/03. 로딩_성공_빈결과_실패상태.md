### Ⅲ. 로딩·성공·빈 결과·실패 상태




# 3-1 화면 상태를 나누는 이유

데이터를 불러오는 화면은 상황에 따라 보여줄 내용이 달라짐

- 요청을 보내고 응답을 기다리는 중
- 데이터를 성공적으로 받음
- 요청은 성공했지만 데이터가 없음
- 요청에 실패함

이 상태를 구분하면 사용자가 현재 상황을 알 수 있고 화면도 알맞게 보여줄 수 있음






# 3-2 화면 상태 타입 만들기

상태를 `enum`으로 정의하면 현재 화면의 상황을 한곳에서 관리할 수 있음

```swift
enum ViewState {
    case loading
    case success
    case empty
    case failure(String)
}
```

- `loading`: 데이터를 불러오는 중
- `success`: 데이터를 받아 화면에 표시할 수 있음
- `empty`: 요청은 성공했지만 표시할 데이터가 없음
- `failure(String)`: 요청에 실패했고 오류 메시지가 있음

`failure(String)`처럼 상태에 연관 값을 넣으면 실패 이유를 함께 저장할 수 있음






# 3-3 ViewModel에서 상태 관리하기

ViewModel에 현재 화면 상태를 저장할 프로퍼티를 둠

```swift
@MainActor
final class CharacterViewModel {
    private(set) var state: ViewState = .loading
    private(set) var characters: [Character] = []
}
```

`private(set)`을 사용하면 ViewModel 안에서는 값을 변경하고 다른 곳에서는 읽기만 할 수 있음






# 3-4 로딩 상태 표시하기

데이터 요청을 시작할 때 상태를 `.loading`으로 바꿈

```swift
func loadCharacters() async {
    state = .loading

    // 데이터 요청
}
```

View는 상태가 `.loading`일 때 로딩 표시를 보여줄 수 있음

```text
빙글빙글 표시
"불러오는 중..."
```

요청이 진행 중임을 표시하면 사용자가 앱이 멈춘 것으로 오해할 가능성을 줄일 수 있음






# 3-5 성공과 빈 결과 구분하기

요청에 성공한 뒤 목록이 비어 있는지 확인함

```swift
if characters.isEmpty {
    state = .empty
} else {
    state = .success
}
```

- 목록에 데이터가 있으면 `.success`
- 목록이 비어 있으면 `.empty`

요청이 성공했다는 것과 화면에 표시할 결과가 있다는 것은 서로 다른 상황임






# 3-6 실패 상태 처리하기

요청 중 오류가 발생하면 상태를 `.failure`로 바꿀 수 있음

```swift
do {
    let result = try await service.fetchCharacters()
    characters = result

    state = result.isEmpty ? .empty : .success
} catch {
    state = .failure("목록을 불러오지 못했어요.")
}
```

오류 메시지를 상태에 함께 저장하면 View에서 사용자에게 안내할 수 있음






# 3-7 전체 ViewModel 예시

```swift
enum ViewState {
    case loading
    case success
    case empty
    case failure(String)
}

@MainActor
final class CharacterViewModel {
    private let service: CharacterService

    private(set) var characters: [Character] = []
    private(set) var state: ViewState = .loading

    init(service: CharacterService) {
        self.service = service
    }

    func loadCharacters() async {
        state = .loading

        do {
            let result = try await service.fetchCharacters()
            characters = result
            state = result.isEmpty ? .empty : .success
        } catch {
            state = .failure("캐릭터 목록을 불러오지 못했어요.")
        }
    }
}
```






# 3-8 상태에 따라 화면 표시하기

View는 ViewModel의 상태를 확인해 상황에 맞는 화면을 보여줄 수 있음

```swift
switch viewModel.state {
case .loading:
    print("불러오는 중")
case .success:
    print("목록 표시")
case .empty:
    print("표시할 결과가 없음")
case .failure(let message):
    print(message)
}
```

실제 화면에서는 `print` 대신 로딩 뷰나 목록 화면, 안내 문구 등을 표시함






# 3-9 다시 시도하기

요청에 실패한 경우 사용자가 다시 시도할 수 있도록 버튼을 제공할 수 있음

```swift
Button("다시 시도") {
    Task {
        await viewModel.loadCharacters()
    }
}
```

다시 요청을 시작할 때 ViewModel이 상태를 `.loading`으로 바꾸므로 로딩 화면을 다시 표시할 수 있음






# 3-10 정리

* 화면 상태는 로딩·성공·빈 결과·실패로 나눌 수 있음
* 요청을 시작할 때 `.loading`으로 설정함
* 데이터가 있으면 `.success`이고 비어 있으면 `.empty`로 처리함
* 요청이 실패하면 오류 메시지와 함께 `.failure`로 설정할 수 있음
* View는 ViewModel의 상태에 따라 알맞은 화면을 표시함
* 실패 상태에서는 다시 시도하는 기능을 제공할 수 있음

> ### ⇒ 화면 상태를 나누면 데이터 요청 중인지 결과가 비었는지 실패했는지 명확하게 보여줄 수 있음 ✨
