### Ⅰ. 서버 통신 전체 흐름 복습


<br>

# 1-1 서버 통신이란?

앱이 서버에 데이터를 요청하고 서버가 그 결과를 돌려주는 과정임 !!

예를 들어 앱에서 치이카와 캐릭터 목록을 보고 싶으면 서버에 목록을 요청하고 서버는 캐릭터 정보를 응답함


> 앱 → 요청 → 서버 \
> 앱 ← 응답 ← 서버


<br>
<br>


# 1-2 요청 주소와 요청 정보 준비하기

서버에 요청할 때는 주소와 함께 필요한 요청 정보를 준비함

- `URL` : 요청할 서버 주소와 경로
- `URLComponents` : Query Parameter가 포함된 URL을 구성할 때 사용
- `URLRequest` : URL, HTTP 메서드, Header, Body 등의 요청 정보를 담음

예를 들어 검색어를 Query Parameter로 보내거나 인증 토큰을 Header에 넣을 수 있음


<br>
<br>


# 1-3 HTTP 메서드와 Body

HTTP 메서드는 요청의 목적을 나타냄

- `GET`: 데이터를 조회할 때 주로 사용
- `POST`: 서버에 데이터를 보내거나 새 데이터를 만들 때 주로 사용

서버에 보낼 데이터가 있다면 요청 Body에 담을 수 있음  
JSON 데이터를 보낼 때는 `JSONEncoder`로 Swift 모델을 `Data`로 변환해 `httpBody`에 설정함


<br>
<br>


# 1-4 URLSession으로 요청 보내기

`URLSession`은 준비한 요청을 서버로 보내고 응답을 받는 역할을 함

```swift
let (data, response) = try await URLSession.shared.data(for: request)
```

- `data` : 서버가 돌려준 응답 본문
- `response` : 상태 코드 등 응답에 관한 정보
- `await` : 비동기 작업의 결과를 기다림
- `try` : 요청 과정에서 발생할 수 있는 오류를 처리하도록 표시

<br>
<br>



# 1-5 응답 확인하기

서버가 응답을 돌려줬다고 해서 요청이 반드시 성공한 것은 아님


HTTP 응답으로 변환한 뒤 상태 코드를 확인해야 함

```swift
guard let httpResponse = response as? HTTPURLResponse else {
    throw URLError(.badServerResponse)
}

guard (200...299).contains(httpResponse.statusCode) else {
    throw URLError(.badServerResponse)
}
```

상태 코드의 구체적인 의미는 API 문서를 확인해야 함


<br>
<br>


# 1-6 JSON 응답 디코딩하기

서버가 JSON을 응답하면 앱에서 사용할 Swift 모델로 변환할 수 있음

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}

let character = try JSONDecoder().decode(
    Character.self,
    from: data
)
```

여러 개의 캐릭터가 배열로 오면 `[Character].self`로 디코딩함

```swift
let characters = try JSONDecoder().decode(
    [Character].self,
    from: data
)
```

JSON의 구조와 키 이름, 자료형은 Swift 모델과 맞아야 함


<br>
<br>


# 1-7 오류 처리하기

네트워크 요청이나 JSON 디코딩 중 오류가 발생할 수 있으므로 `do-catch`로 처리함

```swift
do {
    let (data, response) = try await URLSession.shared.data(for: request)
    let character = try JSONDecoder().decode(Character.self, from: data)
    print(character.name)
} catch {
    print("요청 또는 처리 중 오류 발생:", error)
}
```

네트워크 요청 실패, 서버 상태 코드 오류, JSON 디코딩 오류는 원인이 다를 수 있으므로 각각 확인하는 게 조타

<br>
<br>



# 1-8 네트워크 코드를 분리하기

요청 코드가 화면마다 반복되지 않도록 네트워크 처리를 `APIClient` 같은 타입으로 분리할 수 있음

> View → ViewModel → APIClient → URLSession → 서버

- `View`: 화면을 표시하고 사용자 동작을 전달
- `ViewModel`: 화면에 필요한 데이터와 상태를 관리
- `APIClient`: 요청과 응답 처리를 담당
- `URLSession`: 실제 네트워크 통신을 수행

역할을 나누면 코드의 중복을 줄이고 각 부분을 수정하거나 테스트하기 쉬워짐


<br>
<br>


# 1-9 화면 상태 갱신하기

데이터를 요청할 때는 로딩·성공·빈 결과·실패 상태를 구분할 수 있음

> 요청 시작 → 로딩 → 성공 / 빈 결과 / 실패

ViewModel이 데이터를 받아 상태를 갱신하면 View는 그 상태에 맞는 화면을 보여줌


UI에 연결된 상태를 바꿀 때는 메인 액터에서 처리해야 할 수 있음


<br>
<br>


# 1-10 검색 요청과 디버깅 복습

검색어는 Query Parameter로 서버에 보낼 수 있음  
검색어를 입력할 때마다 요청하면 중복 요청이 많아질 수 있으므로 요청 시점을 조절하거나 이전 요청을 취소할 수 있음

문제가 생기면 다음을 차례로 확인함

1. URL과 경로가 올바른지
2. Query Parameter와 Header가 맞는지
3. 요청 Body의 구조가 맞는지
4. 응답 상태 코드가 무엇인지
5. 응답 JSON과 모델 구조가 맞는지
6. 오류가 요청 단계인지 디코딩 단계인지


<br>
<br>


# 1-12) 정리

* 앱은 서버에 요청을 보내고 응답을 받아 데이터를 사용함
* `URL`, `URLRequest`로 요청을 준비하고 `URLSession`으로 전송함
* 응답의 상태 코드를 확인한 뒤 JSON을 모델로 디코딩함
* 오류가 생길 수 있으므로 `do-catch`로 처리함
* 네트워크 코드는 `APIClient`로 분리하고 ViewModel에서 결과를 화면 상태에 반영할 수 있음
* 문제를 찾을 때는 요청 정보와 응답 상태, JSON 구조를 순서대로 확인함

<br>
