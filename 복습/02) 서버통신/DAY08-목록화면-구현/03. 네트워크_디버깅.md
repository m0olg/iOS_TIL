### Ⅲ. 새로고침과 화면 상태 갱신




# 3-1 새로고침이란?

→ 화면에 표시된 데이터를 서버에 다시 요청해 최신 내용으로 갱신하는 것

목록 화면에서는 사용자가 새로고침 버튼을 누르거나 화면을 아래로 당겨 최신 목록을 불러올 수 있음

```text
새로고침 동작
→ 서버에 다시 요청
→ 응답 데이터로 목록 갱신
→ 화면 업데이트
```






# 3-2 새로고침 함수 만들기

기존 목록을 불러오는 함수를 다시 호출하면 새로고침을 구현할 수 있음

```swift
func refresh() async {
    await loadCharacters()
}
```

목록을 불러오는 코드가 한 곳에 있으면 화면이 처음 나타났을 때나 새로고침할 때 같은 기능을 재사용하기 쉬움






# 3-3 요청 결과로 목록 갱신하기

새 요청에 성공하면 기존 배열을 새 응답으로 바꿈

```swift
func loadCharacters() async {
    do {
        characters = try await apiClient.fetchCharacters()
    } catch {
        print("목록을 불러오지 못했어요:", error)
    }
}
```

`characters`가 바뀌면 관찰 가능한 상태를 통해 화면도 새 데이터에 맞춰 갱신될 수 있음






# 3-4 로딩 상태 갱신하기

새로고침이 진행되는 동안 로딩 상태를 표시할 수 있음

```swift
func loadCharacters() async {
    state = .loading

    do {
        let result = try await apiClient.fetchCharacters()
        characters = result
        state = result.isEmpty ? .empty : .success
    } catch {
        state = .failure("목록을 불러오지 못했어요.")
    }
}
```

요청이 시작될 때 로딩 상태로 바꾸고 요청 결과에 따라 성공·빈 결과·실패 상태로 갱신함






# 3-5 새로고침 중 기존 목록 유지하기

새로고침할 때 기존 목록을 바로 지우지 않고 유지할 수도 있음

```swift
func refresh() async {
    isRefreshing = true
    defer { isRefreshing = false }

    do {
        characters = try await apiClient.fetchCharacters()
    } catch {
        errorMessage = "새로고침에 실패했어요."
    }
}
```

- 요청 중에는 `isRefreshing`으로 새로고침 표시
- 성공하면 새 데이터로 목록 갱신
- 실패하면 기존 목록을 유지하고 오류를 알릴 수 있음
- `defer`는 함수가 끝날 때 지정한 코드를 실행함

기존 목록을 유지할지 로딩 화면으로 바꿀지는 화면 설계에 따라 결정함






# 3-6 새로고침 동작 연결하기

View의 버튼이나 아래로 당기는 동작에서 ViewModel의 새로고침 함수를 호출함

```swift
Task {
    await viewModel.refresh()
}
```

SwiftUI의 목록에서는 화면의 새로고침 기능과 비동기 함수를 연결할 수도 있음

```swift
.refreshable {
    await viewModel.refresh()
}
```

사용하는 화면 구조나 UI 프레임워크에 따라 연결 방법은 달라질 수 있음






# 3-7 요청 실패 후 상태 갱신하기

새로고침 요청이 실패하면 화면 상태와 안내 문구를 갱신할 수 있음

```swift
do {
    characters = try await apiClient.fetchCharacters()
    state = characters.isEmpty ? .empty : .success
} catch {
    state = .failure("다시 불러오지 못했어요.")
}
```

화면에서 재시도 버튼을 제공한다면 버튼을 눌렀을 때 같은 요청 함수를 다시 호출할 수 있음






# 3-8 중복 요청 주의하기

사용자가 짧은 시간 안에 새로고침을 여러 번 하면 요청이 중복될 수 있음

필요하다면 요청 중인지 확인해 중복 요청을 막을 수 있음

```swift
if isRefreshing {
    return
}

isRefreshing = true
defer { isRefreshing = false }
```

중복 요청을 허용할지 막을지는 앱의 동작과 API 특성에 따라 정해야 함






# 3-9 새로고침 전체 예시

```swift
@MainActor
final class CharacterViewModel {
    private let apiClient = CharacterAPIClient()

    private(set) var characters: [Character] = []
    private(set) var isRefreshing = false
    private(set) var errorMessage: String?

    func refresh() async {
        guard !isRefreshing else { return }

        isRefreshing = true
        errorMessage = nil
        defer { isRefreshing = false }

        do {
            characters = try await apiClient.fetchCharacters()
        } catch {
            errorMessage = "목록을 새로고침하지 못했어요."
        }
    }
}
```

이 예시에서는 새로고침 상태와 오류 메시지를 ViewModel에서 관리함  
요청에 성공하면 목록을 새 데이터로 바꾸고 실패하면 오류 메시지를 저장함






# 3-10 정리

* 새로고침은 서버에 데이터를 다시 요청해 화면을 최신 상태로 만드는 기능임
* 기존 데이터 요청 함수를 재사용하면 새로고침을 구현하기 쉬움
* 요청 중·성공·빈 결과·실패에 따라 화면 상태를 갱신할 수 있음
* 새로고침 중 기존 목록을 유지할지 로딩 화면을 보여줄지는 설계에 따라 다름
* 요청이 여러 번 겹치지 않도록 중복 요청을 막을 수 있음
* 화면은 ViewModel의 변경된 상태를 바탕으로 다시 표시됨

> ### ⇒ 새로고침 요청 결과로 ViewModel의 목록과 상태를 갱신하면 화면도 최신 내용으로 바뀜 ✨
