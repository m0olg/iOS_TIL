### Ⅲ. HTTP 요청과 응답, URL

<br>

# 3-1 HTTP란?
→ 클라이언트랑 서버가 요청과 응답을 주고 받을 때 사용하는 통신 규칙

> 앱이 서버에 <mark>데이터를 요청할 땐 HTTP 요청</mark>을 보내고
> 서버는 처리 결과를 <mark>HTTP 응답으로 돌려줌</mark>

HTTPS는 HTTP 통신에 보안 계층을 더한 방식임 \
실제 사용자 정보나 인증 정보가 오갈 수 있으므로 HTTPS를 사용하는 경우가 일반적

<br>
<br>

# 3-2 HTTP 요청의 구성
### 1) 요청 URL
어느 서버의 어떤 기능에 요청할지 나타냄
### 2) HTTP 메서드
요청의 목적을 나타냄

> ex - 데이터를 조회할 땐 `GET`

### 3) 헤더
요청에 필요한 부가 정보를 담음

요런 정보들이 들어갈 수 있음
* 데이터 형식
* 인증 토큰
* 클라이언트가 받을 수 있는 응답 형식

### 4) 본문
서버에 전달할 데이터를 담음, 모든 요청에 본문이 필요한 건 아님

> ex - 게시글을 새로 만들 때 제목과 내용을 본문으로 보낼 수 있음

<br>
<br>

# 3-3 HTTP 응답의 구성
### 1) 상태 코드
요청이 성공 했는지, 요청이나 서버에 문제가 있었는지를 나타냄
### 2) 헤더
응답 데이터 형식이나 응답에 관한 부가 정보를 담음

### 3) 본문
서버가 돌려주는 데이터나 오류 설명을 가지고 있고 응답 본문이 없는 경우도 있음

<br>
<br>


# 3-4 URL의 구성
> URL은 요청할 서버와 자원의 위치를 나타냄

ex - `https://api.example.com/users?page=2`

위 주소는 다음처럼 나눌 수 있음
- `https` : 통신 방식
- `api.example.com` : 호스트 또는 서버 주소
- `/users` : 경로 (Path)
- `page=2` : 쿼리 파라미터


`api.example.com`은 구조를 설명하기 위한 예시 주소이고 실제로 요청을 보내려면 API 제공자가 안내한 주소를 사용해야함

<br>
<br>

# 3-5 Path와 Query Parameter
### 1) Path
→ 서버에서 어떤 자원이나 기능을 요청할지를 나타냄

- `/users` 이건 사용자 목록을 가리킬 수 있음
- `/users/27` 이렇게 하면 특정 사용자를 가리키도록 할 수 있음
    - 여기서 `27`은 사용자 식별자일 수도 있음, 실제 의미는 API 문서에 따라 달라짐

### 2) Query Paramter
→ 요청 조건이나 옵션을 URL에 추가함 보통 `?` 뒤에 작성

* `/users?page=2` - 요기서 `page=2`는 두 번째 페이지를 요청한다는 뜻일 수도 있음
* 여러개의 조건은 `&`로 연결 가능함
    * ✨ **⤷ `/users?page=2&limit=20`**
    - `page=2`: 페이지 번호
    - `limit=20`: 한 번에 요청할 항목 수

각 파라미터의 의미는 API 문서를 확인해야함

<br>
<br>

# 3-6 예시 요청을 읽어보기 !!
다음과 같은 요청이 있다고 치자
- 메서드: `GET`
- URL: `/users?page=2`

이 요청은 보통 "사용자 목록의 두 번째 페이지를 조회해줘"라는 의미 \
다만 API가 실제로 두 번째 페이지를 어떻게 처리하는지는 API 문서에 정의 되어 있음

<br>
<br>

# 3-7 요청과 응답 흐름
1. 앱이 요청 URL과 메서드를 준비
2. 필요한 헤더와 본문을 설정
3. 앱이 서버에 요청을 보냄
4. 서버가 요청을 처리
5. 서버가 상태 코드와 데이터를 응답
6. 앱이 응답을 확인 한 후 필요한 처리를 함

서버가 응답을 받았다고해서 항상 요청이 성공한 것은 아니고 응답의 상태 코드도 함께 확인해야함

<br>
<br>

# 3-8 정리
* HTTP는 클라이언트와 서버가 요청 및 응답을 주고 받는 규칙
* 요청은 URL, 메서드, 헤더, 본문 등으로 구성
* 응답을 상태 코드, 헤더, 본문 등으로 구성
* Path는 요청 대상의 경로를 나타내고 파라미터는 요청 조건을 전달
* 실제 요청 형식은 API 문서를 기준으로 확인 해야함
