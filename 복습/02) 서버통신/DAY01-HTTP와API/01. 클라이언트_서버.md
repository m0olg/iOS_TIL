### I. 클라이언트와 서버

<br>

# 1-1 클라이언트란?
→ 클라이언트는 서버에 데이터나 기능을 요청하는 프로그램 또는 기기


예를 들면 다음과 같음
* 아이폰에서 실행되는 날씨앱
* 웹 브라우저
* 컴퓨터에서 실행되는 메선지 앱 등

iOS 앱 개발에선 우리가 만드는 앱이 클라이언트가 됨 \
앱은 사용자가 화면에서 누르는 버튼이나 입력한 내용을 바탕으로 서버에 요청을 보냄

<br>
<br>

# 1-2 서버란?
→ 서버는 클라이언트의 요청을 받아 처리하고, 그 결과를 응답으로 돌려주는 컴퓨터 프로그램

서버는 다음과 같은 일을 할 수 있음
* 사용자 정보 저장 및 조회
* 게시글이나 상품 정보 제공
* 로그인 여부 확인
* 결제 요청 처리
* 다른 서비스의 데이터 조회 등

앱이 종료 되어도 서버의 데이터는 유지, 그래서 여러 기기에서 같은 계정으로 로그인해도 같은 사용자 정보를 볼 수 있는 것임

<br>
<br>

# 1-3 클라이언트와 서버 통신
> 클라이언트와 서버는 보통 <mark>네트워크를 통해 요청(리퀘스트 Request)과 응답(리스폰 Response)</mark>을 주고 받음

1. 사용자가 앱에서 동작을 수행
2. 앱이 서버에 요청을 보냄
3. 서버가 요청을 확인하고 처리
4. 서버가 결과를 응답으로 돌려줌
5. 앱이 응답을 해석해 화면에 보여줌

예를 들어 날씨 앱에서 날씨를 확인하는 과정은 다음과 같음
1. 사용자가 날씨 화면을 엶
2. 앱이 서버에 날씨 정보를 요청
3. 서버가 날씨 데이터를 조회
4. 서버가 기온과 날씨 상태를 ㅇ응답
5. 앱이 응답을 읽어 화면에 표시

<br>
<br>

# 1-4 앱 안에 데이터를 저장하면 안 될까?
* 앱 안에 저장한 데이터는 해당 기기에서만 사용할 수 있는 경우가 많음
    - ⤷ 🚨 그래서 앱을 삭제하거나 기기를 바꾸면 데이터가 사라질 수도 있음
* 근데 서버에 데이터를 저장하면 여러 기기에서 같은 데이터를 이용하거나 다른 사용자와 데이터 공뷰가 가능함 ✨

<br>
<br>

# 1-5 API란?
→ API는 서로 다른 프로그램이 정해진 방식으로 기능이나 데이터를 주고 받기 위한 약속

iOS 앱은 서버 내부의 DB나 코드를 직접 다루진 않음\ 대신, 서버가 제공하는 API를 통해 필요한 기능을 요청

예를 들어 서버가 다음 기능을 API로 제공한다고 치고
```
- 사용자 목록 조회
- 새 게시글 작성
- 게시글 수정
- 게시글 삭제
```
앱은 정해진 형식에 맞춰 API를 호출하고 서버가 돌려주는 응답을 사용

<br>
<br>

# 1-6 API 문서란?
→ API 문서는 각 기능을 어떻게 요청 해야하는지 설명하는 안내서

보통 다음과 같은 정보가 담겨져 있음
- 요청 URL
- HTTP 메서드
- 필요한 헤더
- 요청 본문 형식
- 응답 형식
- 응답 상태 코드
- 인증 필요 여부

API 문서를 확인하지 않고 요청을 만들면 주소, 필수 값, 데이터 형식이 맞지 않아 요청이 실패할 가능성이 있음

<br>

## ✨ 정리
- iOS 앱은 서버에 요청을 보내는 클라이언트
- 서버는 요청을 처리하고 응답을 돌려줌
- API는 앱과 서버가 기능이나 데이터를 주고 받는 약속
- API 문서에서 요청 방식과 응답 형식을 확인해야함
