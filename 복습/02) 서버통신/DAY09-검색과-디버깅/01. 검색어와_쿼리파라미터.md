### Ⅰ. 검색어와 Query Parameter




# 1-1 검색어를 서버에 보내는 이유

앱에서 사용자가 검색어를 입력하면, 그 검색어를 서버에 보내 원하는 데이터를 요청할 수 있음

예를 들어 치이카와 캐릭터 목록에서 `하치와레`를 검색하면 검색어를 서버에 전달하고, 서버가 관련 결과를 돌려줄 수 있음

> 검색어 입력 → 서버에 검색 요청 → 검색 결과 받기 → 화면에 표시






# 1-2 검색어와 Query Parameter

검색어는 Query Parameter로 URL에 포함해 보낼 수 있음

```text
https://api.example.com/characters?query=하치와레
```

- `?`: Query Parameter가 시작되는 위치
- `query`: 파라미터 이름
- `하치와레`: 검색어 값

파라미터 이름은 API마다 다를 수 있으므로 API 문서를 확인해야 함






# 1-3 URLComponents로 검색어 구성하기

검색어를 URL에 직접 이어 붙이기보다 `URLComponents`와 `URLQueryItem`을 이용해 구성할 수 있음

```swift
var components = URLComponents()
components.scheme = "https"
components.host = "api.example.com"
components.path = "/characters"
components.queryItems = [
    URLQueryItem(name: "query", value: "하치와레")
]

guard let url = components.url else {
    return
}
```

`URLComponents`를 사용하면 공백이나 특수문자가 포함된 검색어도 URL에 맞게 구성하기 쉬움






# 1-4 검색어가 비어 있을 때

검색어가 비어 있다면 검색 요청을 보내지 않거나 전체 목록을 요청하도록 처리할 수 있음

```swift
let trimmedQuery = query.trimmingCharacters(in: .whitespacesAndNewlines)

guard !trimmedQuery.isEmpty else {
    return
}
```

`trimmingCharacters`를 사용하면 검색어 앞뒤의 공백과 줄바꿈을 정리할 수 있음






# 1-5 검색어 입력과 요청 시점

검색어를 입력할 때마다 바로 요청을 보내면 글자를 한 글자씩 입력할 때마다 요청이 발생할 수 있음

예를 들어 `하치와레`를 입력하면 다음과 같이 여러 번 요청될 수 있음

```
하
→ 하치
→ 하치와
→ 하치와레
```

검색 방식에 따라 입력이 끝난 뒤 검색 버튼을 눌렀을 때 요청하거나 입력을 잠시 멈춘 뒤 요청하도록 구성할 수 있음






# 1-6 검색 결과 디코딩하기

검색 결과가 여러 캐릭터의 JSON 배열이라면 배열 모델로 디코딩할 수 있음

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}

let characters = try JSONDecoder().decode(
    [Character].self,
    from: data
)
```

실제 응답이 객체 안에 배열을 담고 있다면 전체 응답 구조에 맞는 모델을 만들어야 함






# 1-7 정리

* 검색어를 서버에 보내면 조건에 맞는 데이터를 요청할 수 있음
* 검색어는 보통 Query Parameter로 URL에 전달함
* `URLComponents`와 `URLQueryItem`으로 검색 URL을 구성할 수 있음
* 검색어가 비어 있는 경우 요청을 보낼지 확인해야 함
* 검색 입력마다 요청하면 요청이 너무 많이 생길 수 있어 요청 시점을 고려해야 함
* 실제 파라미터 이름과 응답 구조는 API 문서를 기준으로 확인해야 함

> ### ⇒ 검색어를 Query Parameter로 서버에 보내고, 돌려받은 결과를 화면에 표시 ✨
