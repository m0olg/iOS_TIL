### Ⅱ. 중복 요청과 요청 취소




# 2-1 중복 요청이란?

→ 같은 요청이 짧은 시간 안에 여러 번 보내지는 상황

예를 들어 치이카와 검색창에 `하치와레`를 입력할 때 글자마다 요청하면 검색 요청이 여러 번 발생할 수 있음

```text
하 → 요청
하치 → 요청
하치와 → 요청
하치와레 → 요청
```

요청이 중복되면 서버와 앱이 불필요한 일을 더 하게 되고, 응답이 도착하는 순서도 달라질 수 있음






# 2-2 응답 순서가 바뀌는 문제

먼저 보낸 요청이 항상 먼저 도착하는 것은 아님

예를 들어 `하치` 검색 결과보다 `하치와레` 검색 결과가 먼저 도착할 수 있음  
이후 늦게 도착한 이전 검색 결과가 화면을 덮어쓰면 현재 검색어와 다른 결과가 표시될 수 있음

> 하치 검색 요청 → 하치와레 검색 요청 → 하치와레 결과 도착 → 하치 결과가 나중에 도착해 화면을 덮음






# 2-3 요청 중인지 확인하기

같은 요청이 동시에 실행되지 않도록 요청 상태를 관리할 수 있음

```swift
if isLoading {
    return
}

isLoading = true
defer { isLoading = false }
```

- `isLoading`: 요청이 진행 중인지 나타내는 값
- 요청 중이면 새 요청을 시작하지 않음
- `defer`: 함수가 끝날 때 로딩 상태를 해제함

이 방법은 중복 요청을 막는 간단한 방식이지만 새 요청을 항상 허용해야 하는 검색에서는 상황에 맞게 다른 방법을 선택해야 함






# 2-4 이전 요청 취소하기

새 검색어가 들어오면 이전 요청을 취소하고 최신 검색 요청만 처리할 수 있음

```swift
private var searchTask: Task<Void, Never>?

func search(_ query: String) {
    searchTask?.cancel()

    searchTask = Task {
        await performSearch(query)
    }
}
```

새 검색을 시작하기 전에 기존 `Task`를 취소함  
다만 요청을 취소해도 이미 서버에서 처리 중인 작업까지 반드시 중단되는 것은 아니며 취소 결과를 코드에서 확인해야 함






# 2-5 취소된 작업 확인하기

작업이 취소되었는지 확인해 불필요한 처리를 막을 수 있음

```swift
func performSearch(_ query: String) async {
    do {
        let results = try await service.search(query)

        guard !Task.isCancelled else {
            return
        }

        characters = results
    } catch {
        if Task.isCancelled {
            return
        }

        errorMessage = "검색에 실패했어요 ㅠㅠ"
    }
}
```

취소된 이전 요청의 결과가 도착해도 화면을 갱신하지 않도록 확인함






# 2-6 검색 입력 후 잠시 기다리기

검색어를 입력할 때마다 즉시 요청하지 않고, 입력이 잠시 멈춘 뒤 요청하는 방법도 있음  
이 방식을 **디바운스**라고 함

> 하 입력 → 잠시 기다림 → 치 입력 → 기다리는 시간 다시 시작 → 하치와레 입력 후 입력이 멈춤 → 검색 요청

디바운스를 사용하면 사용자가 입력하는 동안 발생하는 불필요한 요청을 줄일 수 있음






# 2-7 요청 취소 시 주의할 점

- 취소된 요청의 결과가 화면을 덮어쓰지 않도록 확인해야 함
- 요청 취소가 서버의 작업까지 되돌린다는 뜻은 아님
- 취소를 오류로 보여줄지 조용히 무시할지는 앱 동작에 맞춰 정해야 함
- 검색 요청을 막을지 이전 요청을 취소할지는 기능에 따라 선택해야 함






# 2-8 정리

* 중복 요청은 같은 요청이 여러 번 발생하는 상황임
* 여러 요청의 응답 순서가 바뀌면 오래된 결과가 최신 화면을 덮을 수 있음
* 로딩 상태로 요청 중복을 막을 수 있음
* `Task`를 저장해 이전 비동기 작업을 취소할 수 있음
* 취소된 요청의 결과가 화면에 반영되지 않도록 취소 여부를 확인해야 함
* 디바운스를 사용하면 입력이 잠시 멈춘 뒤 검색해 요청 수를 줄일 수 있음

> ### ⇒ 검색 중에는 요청이 겹치지 않게 관리하고, 오래된 결과가 화면에 표시되지 않도록 해야 함 ✨
