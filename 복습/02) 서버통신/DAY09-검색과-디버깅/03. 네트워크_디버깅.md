### Ⅲ. 네트워크 디버깅




# 3-1 네트워크 디버깅이란?

→ 서버 요청이 예상대로 동작하지 않을 때 요청과 응답을 확인해 원인을 찾는 것

예를 들어 치이카와를 검색했는데 결과가 안 나오면 검색어가 잘 전달됐는지 서버가 어떤 응답을 줬는지 확인해야 함






# 3-2 먼저 확인할 것

네트워크 오류가 생기면 다음 항목을 순서대로 확인하면 원인을 찾기 쉬움

1. URL과 경로가 올바른지
2. HTTP 메서드가 맞는지
3. Query Parameter와 Header가 올바른지
4. 요청 Body가 필요한 형식인지
5. 서버 응답의 상태 코드가 무엇인지
6. 응답 데이터가 예상한 JSON 구조와 맞는지






# 3-3 요청 주소와 파라미터 확인하기

검색 요청을 보낼 때는 URL에 검색어가 제대로 포함됐는지 확인함

```text
https://api.example.com/characters?query=하치와레
```

검색어가 비어 있거나 파라미터 이름이 API 문서와 다르면 원하는 결과를 받지 못할 수 있음

`URLComponents`에서 최종 URL을 출력하면 요청 주소를 확인하는 데 도움이 됨 !!

```swift
print(url)
```






# 3-4 상태 코드 확인하기

응답을 받았다면 HTTP 상태 코드를 확인함

```swift
guard let httpResponse = response as? HTTPURLResponse else {
    print("HTTP 응답이 아님")
    return
}

print("상태 코드:", httpResponse.statusCode)
```

상태 코드는 요청 처리 결과를 파악하는 단서임

- `200`번대: 보통 성공 응답
- `400`번대: 요청이나 인증 등에 문제가 있을 수 있음
- `500`번대: 서버에서 문제가 발생했을 수 있음

정확한 의미는 사용하는 API 문서를 확인해야 함






# 3-5 응답 본문 확인하기

상태 코드가 성공이더라도 응답 내용이 예상과 다를 수 있음  
응답 `Data`를 문자열로 변환해 JSON 내용을 확인할 수 있음

```swift
let responseText = String(data: data, encoding: .utf8)
print(responseText ?? "응답 내용을 문자열로 바꿀 수 없음")
```

예를 들어 치이카와 목록을 기대했는데 오류 메시지가 왔다면 응답 본문에서 이유를 찾을 수 있음






# 3-6 디코딩 오류 확인하기

JSON 응답을 모델로 바꾸는 데 실패하면 JSON 구조와 Swift 모델을 비교함

확인할 내용은 다음과 같음

- JSON이 배열인지 객체인지
- 필요한 키가 있는지
- JSON 값의 자료형과 모델 프로퍼티 타입이 맞는지
- 값이 빠질 수 있는데 필수 프로퍼티로 선언하지 않았는지
- 키 이름이 다르면 `CodingKeys`를 설정했는지

```swift
do {
    let characters = try JSONDecoder().decode(
        [Character].self,
        from: data
    )
    print(characters)
} catch {
    print("디코딩 실패 :", error)
}
```






# 3-7 오류 종류를 나누어 확인하기

네트워크 요청 자체가 실패한 경우와 서버 응답을 받았지만 상태 코드가 실패인 경우는 다름

### 1) 요청 자체가 실패한 경우

인터넷 연결이나 URL 문제 등으로 요청에 실패하면 `catch`에서 확인함

### 2) 서버 응답을 받았지만 실패한 경우

서버가 `404`나 `500` 같은 상태 코드를 보냈다면 `statusCode`와 응답 본문을 확인함

### 3) 디코딩에 실패한 경우

응답은 받았지만 JSON 구조와 모델이 맞지 않는지 확인함






# 3-8 디버깅할 때 주의할 점

- 인증 토큰이나 개인정보를 로그에 그대로 출력하지 않기
- 실제 서버 주소와 요청 형식을 API 문서와 비교하기
- 오류가 난 위치를 나눠서 확인하기
- 응답 JSON이 항상 같은 구조라고 가정하지 않기
- 문제를 확인한 뒤 불필요한 로그는 정리하기






# 3-9 정리

* 네트워크 디버깅은 요청과 응답을 확인해 문제의 원인을 찾는 과정임
* URL과 Query Parameter가 올바른지 먼저 확인
* 상태 코드와 응답 본문을 함께 살펴봄
* 디코딩 오류가 나면 실제 JSON과 Swift 모델의 구조를 비교함
* 요청 실패와 서버 오류 응답 그리고 디코딩 오류를 구분해 확인
* 로그에 인증 토큰이나 개인정보를 남기지 않도록 주의
