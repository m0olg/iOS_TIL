### I. GET 요청·응답 확인

<br>


# 1-1 GET 요청이란?

→ 서버에 있는 데이터를 조회할 때 사용하는 HTTP 요청 방식

예를 들어 캐릭터 목록을 가져오고 싶을 때 `GET` 요청을 보낼 수 있음

```text
GET /characters
```

GET 요청은 보통 서버의 데이터를 가져오는 용도로 사용함  
실제 요청 주소와 경로는 API 문서를 확인해야 함


<br>
<br>


# 1-2 URLSession이란?

→ iOS 앱에서 서버와 네트워크 통신을 할 때 사용하는 기본 도구

`URLSession`을 이용해 요청을 보내고, 서버가 돌려준 응답 데이터를 받을 수 있음. Apple 문서에서도 `URLSession`을 URL로 지정한 곳에 데이터를 다운로드하거나 업로드하는 API로 설명함. ([Apple Developer Documentation](https://developer.apple.com/documentation/foundation/urlsession))



<br>
<br>

# 1-3 GET 요청 보내기

서버에 요청하려면 먼저 주소를 `URL`로 만들고, `URLSession`으로 데이터를 요청함

```swift
import Foundation

let url = URL(string: "https://api.example.com/characters")!

let (data, response) = try await URLSession.shared.data(from: url)
```

- `URL(string:)`: 요청할 주소를 `URL`로 만듦
- `URLSession.shared`: 기본 설정의 세션을 사용
- `data(from:)`: 해당 주소에 요청을 보내고 응답 데이터와 응답 정보를 받음
- `data`: 서버가 돌려준 본문 데이터
- `response`: 서버 응답에 관한 정보

`api.example.com`은 예시 주소이므로 실제 요청에는 API 제공자가 안내한 주소를 사용해야 함


<br>
<br>


# 1-4 응답 상태 코드 확인하기

서버 응답을 받았다고 해서 요청이 항상 성공한 것은 아님  
응답의 상태 코드를 확인해야 요청 결과를 판단할 수 있음

```swift
guard let httpResponse = response as? HTTPURLResponse else {
    throw URLError(.badServerResponse)
}

print(httpResponse.statusCode)
```

`HTTPURLResponse`는 HTTP 응답의 상태 코드 등 HTTP 관련 정보를 제공함. ([Apple Developer Documentation](https://developer.apple.com/documentation/foundation/httpurlresponse))

자주 볼 수 있는 상태 코드는 다음과 같음

- `200`: 요청 성공
- `201`: 요청으로 새로운 데이터가 만들어짐
- `400`: 요청 형식이나 값에 문제가 있을 수 있음
- `401`: 인증이 필요하거나 인증 정보가 유효하지 않을 수 있음
- `404`: 요청한 자원을 찾을 수 없음
- `500`: 서버 내부에서 문제가 발생함

상태 코드의 의미와 사용 방식은 API마다 다를 수 있으므로 API 문서도 확인해야 함


<br>
<br>



# 1-5 상태 코드로 성공 여부 확인하기

네트워크 통신 자체가 성공해도 서버가 오류 상태 코드를 보낼 수 있음  
그래서 상태 코드 범위를 확인해 성공 응답인지 구분할 수 있음

```swift
guard (200...299).contains(httpResponse.statusCode) else {
    throw URLError(.badServerResponse)
}
```

위 코드는 상태 코드가 `200`부터 `299` 사이가 아니면 오류로 처리함

> 응답을 받음 ≠ 요청이 성공함  
> 응답 상태 코드까지 확인해야 함



<br>
<br>


# 1-6 응답 데이터 확인하기

서버 응답 본문은 `Data` 타입으로 들어옴  
JSON 응답이라면 데이터를 바로 출력하기보다, 우선 문자열로 바꿔 내용을 확인할 수 있음

```swift
let responseText = String(data: data, encoding: .utf8)
print(responseText ?? "응답 내용을 문자열로 변환할 수 없음")
```

실제 앱에서는 응답 JSON 구조에 맞는 모델을 만들고 `JSONDecoder`로 디코딩해 사용함


<br>
<br>



# 1-7 GET 요청과 응답 확인 예시

```swift
import Foundation

let url = URL(string: "https://api.example.com/characters")!

do {
    let (data, response) = try await URLSession.shared.data(from: url)

    guard let httpResponse = response as? HTTPURLResponse else {
        throw URLError(.badServerResponse)
    }

    print("상태 코드:", httpResponse.statusCode)

    guard (200...299).contains(httpResponse.statusCode) else {
        throw URLError(.badServerResponse)
    }

    let responseText = String(data: data, encoding: .utf8)
    print("응답 내용:", responseText ?? "문자열 변환 실패")
} catch {
    print("요청 실패:", error)
}
```

이 코드는 다음 순서로 동작함

1. 요청할 URL을 만듦
2. `URLSession`으로 GET 요청을 보냄
3. 응답에서 HTTP 상태 코드를 확인
4. 성공 상태 코드인지 검사
5. 응답 본문을 문자열로 바꿔 출력
6. 요청이나 처리 중 오류가 나면 `catch`에서 출력

`data(from:)`는 비동기 함수이므로 `await`가 필요하고, 오류가 발생할 수 있어 `try`로 호출함

<br>



# 1-8 URLRequest로 요청 정보 설정하기

간단한 GET 요청은 `data(from:)`로 보낼 수 있음  
요청에 필요한 메서드나 헤더 등을 직접 설정하고 싶다면 `URLRequest`를 사용할 수 있음

```swift
var request = URLRequest(url: url)
request.httpMethod = "GET"
request.setValue("application/json", forHTTPHeaderField: "Accept")

let (data, response) = try await URLSession.shared.data(for: request)
```

- `URLRequest`: 요청 주소, 메서드, 헤더 등 요청 정보를 담음
- `httpMethod`: HTTP 메서드를 설정
- `setValue`: 요청 헤더를 설정
- `data(for:)`: 설정한 요청을 보내고 응답을 받음

`Accept` 헤더는 클라이언트가 어떤 형식의 응답을 받을 수 있는지 서버에 알려줄 때 사용함. 필요한 헤더는 API 문서를 확인해야 함


<br>
<br>



# 1-9 요청 실패와 HTTP 오류 구분하기

요청이 실패하는 상황은 크게 나눠서 확인할 수 있음

### 1) 네트워크 요청 자체가 실패한 경우

인터넷 연결 문제, 잘못된 URL 등으로 응답을 받지 못할 수 있음  
이런 오류는 `catch`에서 확인함

### 2) 서버 응답은 받았지만 상태 코드가 성공이 아닌 경우

서버가 `404`, `500` 같은 상태 코드를 응답할 수 있음  
이때는 `HTTPURLResponse`의 `statusCode`를 확인해야 함

즉, `catch`로 잡히는 통신 오류와 HTTP 상태 코드 오류는 구분해서 확인해야 함



<br>
<br>


# 1-10 정리

* `URLSession`은 iOS 앱에서 서버에 요청을 보내고 응답을 받는 데 사용함
* GET 요청은 주로 서버 데이터를 조회할 때 사용함
* `data`는 서버가 돌려준 응답 본문임
* `HTTPURLResponse`에서 상태 코드를 확인할 수 있음
* 응답을 받았더라도 상태 코드가 성공 범위인지 확인해야 함
* JSON 응답은 보통 `JSONDecoder`로 앱의 모델 타입으로 변환함
* 실제 URL, 요청 헤더, 응답 형식은 API 문서를 기준으로 확인해야 함

<br>

> ### ⇒ GET 요청을 보낸 뒤에는 통신 오류뿐 아니라 HTTP 상태 코드와 응답 데이터도 확인해야 함 ✨
