### Ⅲ. GET 요청·응답 확인

<br>


# 3-1 GET 요청이란?

→ 서버에 있는 데이터를 조회할 때 사용하는 HTTP 요청 방식

예를 들어 서버에서 치이카와 캐릭터 정보를 가져오고 싶을 때 `GET` 요청을 보낼 수 있음

```text
GET /characters
```

GET 요청은 보통 데이터를 조회할 때 사용함  
실제 주소와 경로는 API 문서를 확인해야 함


<br>
<br>


# 3-2 URLSession으로 GET 요청 보내기

간단한 GET 요청은 `URLSession.shared.data(from:)`로 보낼 수 있음

```swift
import Foundation

let url = URL(string: "https://api.example.com/characters")!

let (data, response) = try await URLSession.shared.data(from: url)
```

- `url`: 요청할 서버 주소
- `data`: 서버가 돌려준 응답 본문
- `response`: 서버 응답 정보

`api.example.com`은 예시 주소임  
실제로 요청할 때는 API 제공자가 안내한 주소를 사용해야 함


<br>
<br>



# 3-3 HTTPURLResponse로 응답 확인하기

`response`에는 여러 종류의 응답 정보가 들어올 수 있음  
HTTP 상태 코드를 확인하려면 `HTTPURLResponse`로 변환해야 함

```swift
guard let httpResponse = response as? HTTPURLResponse else {
    throw URLError(.badServerResponse)
}

print(httpResponse.statusCode)
```

`statusCode`는 서버가 요청을 어떻게 처리했는지 나타냄

자주 볼 수 있는 상태 코드는 다음과 같음

- `200`: 요청 성공
- `201`: 요청으로 새 데이터가 만들어짐
- `400`: 요청에 문제가 있을 수 있음
- `401`: 인증이 필요하거나 인증 정보에 문제가 있을 수 있음
- `404`: 요청한 자원을 찾을 수 없음
- `500`: 서버 내부에 문제가 발생함

상태 코드의 의미는 API 문서도 함께 확인해야 함

<br>
<br>

# 3-4 상태 코드로 성공 여부 확인하기

서버에서 응답을 받았더라도 요청이 성공했다는 뜻은 아님  
상태 코드가 성공 범위인지 확인해야 함

```swift
guard (200...299).contains(httpResponse.statusCode) else {
    throw URLError(.badServerResponse)
}
```

`200...299`는 `200`부터 `299`까지의 범위를 뜻함

> 응답을 받음 ≠ 요청 성공  
> 상태 코드도 확인해야 함

<br>
<br>




# 3-5 응답 본문 확인하기

서버가 돌려준 `data`는 `Data` 타입임  
응답이 JSON이라면 문자열로 바꿔 내용을 확인할 수 있음

```swift
let responseText = String(data: data, encoding: .utf8)
print(responseText ?? "응답 내용을 읽을 수 없음")
```

실제 앱에서는 응답 내용을 출력하는 대신, JSON 구조에 맞는 모델로 디코딩해 사용할 수 있음




<br>

# 3-6 요청 실패와 서버 오류 구분하기

### 1) 요청 자체가 실패한 경우

인터넷 연결 문제나 잘못된 주소 등으로 서버 응답을 받지 못할 수 있음  
이런 오류는 `catch`에서 확인함

### 2) 서버 응답을 받았지만 실패 상태 코드인 경우

서버 응답은 받았지만 상태 코드가 `404`나 `500`일 수 있음  
이때는 `HTTPURLResponse`의 `statusCode`를 확인해야 함

즉, 네트워크 요청 오류와 HTTP 상태 코드 오류는 구분해서 확인해야 함



<br>
<br>


# 3-7 전체 요청 예시

```swift
import Foundation

func fetchCharacters() async {
    guard let url = URL(string: "https://api.example.com/characters") else {
        print("URL이 올바르지 않음")
        return
    }

    do {
        let (data, response) = try await URLSession.shared.data(from: url)

        guard let httpResponse = response as? HTTPURLResponse else {
            throw URLError(.badServerResponse)
        }

        print("상태 코드:", httpResponse.statusCode)

        guard (200...299).contains(httpResponse.statusCode) else {
            throw URLError(.badServerResponse)
        }

        let responseText = String(data: data, encoding: .utf8)
        print("응답 내용:", responseText ?? "문자열 변환 실패")

    }
}
```

이 코드는 다음 순서로 동작함

1. 요청할 URL을 만듦
2. `URLSession`으로 GET 요청을 보냄
3. HTTP 응답인지 확인
4. 상태 코드가 성공 범위인지 확인
5. 응답 본문을 문자열로 바꿔 출력
6. 요청 중 오류가 발생하면 `catch`에서 처리

# 3-8 정리

* GET 요청은 주로 서버 데이터를 조회할 때 사용함
* `URLSession`으로 요청을 보내고 응답의 `data`, `response`를 받음
* `HTTPURLResponse`의 `statusCode`로 응답 상태를 확인함
* 서버 응답을 받았더라도 상태 코드가 성공 범위인지 확인해야 함
* 네트워크 오류와 HTTP 오류는 구분해서 처리해야 함
* 실제 주소와 응답 형식은 API 문서를 기준으로 확인해야 함

<br>

> ### ⇒ GET 요청을 보낸 뒤 상태 코드와 응답 본문을 확인하면 됨 ✨
