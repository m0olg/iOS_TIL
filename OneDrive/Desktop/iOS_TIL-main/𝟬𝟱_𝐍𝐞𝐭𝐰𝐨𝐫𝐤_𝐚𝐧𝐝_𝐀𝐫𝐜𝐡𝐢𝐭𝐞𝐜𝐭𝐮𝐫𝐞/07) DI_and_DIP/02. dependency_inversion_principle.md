## DIP
# 01 DIP란?
→ DIP는 **객체가 구체적인 클래스에 직접 의존하지 않고 프로토콜과 같은 추상화에 의존해야 한다는 원칙** (고수준 모듈과 저수준 모듈이 모두 추상화에 의존해야함)

<br>
<br>

# 02 예시
> DIP를 적용하지 않은 경우
```swift
class Agent {
    let name : String

    init (name : String) {
        self.name = name
    }
}

class Player {
    let agent : Agent

    init (agent : Agent) {
        self.agent = agent
    }
}
```
이 코드에서 `Player`는 구체적인 클래스인 `Agent`에 직접 의존함


따라서 `Agent`를 다른 객체로 바꾸거나 수정하면 `Player`도 영향을 받을 수 있음

<br>
<br>

# 03 DIP를 적용한 경우
먼저 프로토콜을 정의 !!
```swift
protocol AgentType {
    var name : String { get }
}
```
`Agent`가 프로토콜을 채택
```swift
class Agent : AgentType {
    let name : String

    init (name : String) {
        self.name = name
    }
}
```
`Player`는 이제 `Agent`가 아닌 `AgentType`에 의존


의존성 관계는 다음과 같음 : <mark>Player → AgentType ← Agent</mark>

`Player`와 `Agent`가 직접 연결되지 않고 둘 다 `AgentType`이라는 추상화에 의존

<br>
<br>

# 04 다른 에이전트로 교체하는 법
`AgentType`을 채택한 객체라면 `Player`에 전달할 수 있음
```swift
class MockAgent: AgentType {
    let name = "테스트 에이전트"
}

let player = Player(agent: MockAgent())
```
`Player`의 코드를 수정하지 않고도 `Agent`를 `MockAgent`로 교체 가능

<br>
<br>

# 05 DI와 DIP의 차이
| 개념 | 의미 |
| :--- | :--- |
| **DI** | 필요한 객체를 외부에서 전달받는 방법 |
| **DIP** | 구체적인 클래스보다 추상화에 의존해야 한다는 원칙 |

### ① DI만 적용한 경우
```swift
class Player {
    let agent: Agent

    init(agent: Agent) {
        self.agent = agent
    }
}
```
`Agent`를 외부에서 받으므로 DI는 적용됐지만 여전히 구체적인 `Agent`에 의존

### ② DI와 DIP를 함께 적용한 경우
```swift
class Player {
    let agent: AgentType

    init(agent: AgentType) {
        self.agent = agent
    }
}
```
* 외부에서 객체를 전달받음 → **DI**
* 프로토콜에 의존함 → **DIP**

# 06 정리
* **DIP**는 구체적인 클래스가 아닌 추상화에 의존하라는 원칙
* Swift에서는 주로 **프로토콜**을 사용해 DIP를 적용
* `Player`가 `Agent`에 직접 의존하면 결합도가 높아짐
* `Player`가 `AgentType`에 의존하면 에이전트 교체와 테스트가 쉬워짐
* **DI는 의존성을 주입하는 방법**이고 **DIP는 의존할 대상을 정하는 원칙**
