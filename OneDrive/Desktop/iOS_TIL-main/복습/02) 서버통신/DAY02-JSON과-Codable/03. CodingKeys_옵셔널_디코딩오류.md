### Ⅲ. CodingKeys, 옵셔널, 디코딩 오류

<br>


# 3-1 CodingKeys란?

서버 JSON의 키 이름과 Swift 프로퍼티 이름이 다를 때 두 이름을 연결하는 방법

예를 들어 서버 응답이 다음과 같다고 하자

```json
{
  "character_id": 1,
  "character_name": "치이카와"
}
```

Swift에서는 `characterId`, `characterName`처럼 이름을 쓰고 싶을 수 있음

```swift
struct Character: Decodable {
    let characterId: Int
    let characterName: String

    enum CodingKeys: String, CodingKey {
        case characterId = "character_id"
        case characterName = "character_name"
    }
}
```

- `characterId`: Swift에서 사용할 프로퍼티 이름
- `"character_id"`: JSON에 실제로 들어 있는 키

`CodingKeys`는 JSON에 있는 키를 바꾸는 게 아니라, JSON 키와 Swift 프로퍼티를 연결해 주는 역할을 함

> JSON의 `character_id` → Swift의 `characterId`

JSON 키가 Swift 프로퍼티 이름과 이미 같다면 해당 항목은 `CodingKeys`에 꼭 적지 않아도 됨


<br>
<br>



# 3-2 키 이름이 같은 경우

JSON 키와 Swift 프로퍼티 이름이 같으면 `CodingKeys`를 생략해도 됨

### JSON ⬇️⬇️

```json
{
  "id": 1,
  "name": "치이카와"
}
```

### Swift 모델 ⬇️⬇️

```swift
struct Character: Decodable {
    let id: Int
    let name: String
}
```

<br>
<br>





# 3-3 서버 값이 없을 수 있을 때

응답 값이 항상 오는 게 아니라면 프로퍼티를 옵셔널로 선언할 수 있음

```swift
struct Character: Decodable {
    let id: Int
    let name: String
    let nickname: String?
}
```

`nickname`은 값이 있을 수도 있고 없을 수도 있음

JSON에 키가 없거나 값이 `null`인 경우를 허용하려면 `String?`처럼 옵셔널로 표현함

하지만 필수 값까지 무조건 옵셔널로 만들기보다는, 실제 API 응답과 API 문서를 확인해 필요한 값만 옵셔널로 선언하는 게 좋음



<br>
<br>


# 3-4 디코딩 오류가 발생하는 대표적인 경우

### 1) JSON 키가 맞지 않는 경우

Swift 모델에서 필요한 키를 찾지 못하면 디코딩에 실패할 수 있음

### 2) 자료형이 맞지 않는 경우

JSON 값이 문자열인데 Swift 모델은 숫자로 선언하는 등 자료형이 다르면 오류가 발생할 수 있음

```json
{
  "age": "3"
}
```

```swift
struct Character: Decodable {
    let age: Int
}
```

위 응답의 `"age"`는 문자열인데 모델은 `Int`를 기대하므로 기본 설정으로는 디코딩되지 않을 수 있음

### 3) 필수 값이 빠진 경우

옵셔널이 아닌 프로퍼티에 해당하는 키가 JSON에 없으면 디코딩에 실패할 수 있음

### 4) JSON 구조가 다른 경우

객체를 기대했는데 배열이 오거나, 배열을 기대했는데 객체가 오는 등 구조가 다르면 실패할 수 있음


<br>
<br>



# 3-5 디코딩 오류 확인하기

디코딩 오류가 발생했을 때 오류를 출력하면 원인을 파악하는 데 도움이 됨

```swift
do {
    let character = try JSONDecoder().decode(Character.self, from: data)
    print(character)
} catch {
    print("디코딩 실패:", error)
}
```

오류가 나면 다음을 확인해보기

1. 실제 응답 JSON이 예상한 구조인지 확인
2. JSON 키와 `CodingKeys`가 맞는지 확인
3. JSON 값과 Swift 프로퍼티의 자료형이 맞는지 확인
4. 값이 빠질 수 있는데 옵셔널로 선언하지 않았는지 확인
5. 서버 응답이 오류 메시지나 다른 형식으로 오지 않았는지 확인


<br>
<br>



# 3-6 디코딩할 때 자주 하는 실수

### 1) 서버 응답을 확인하지 않고 모델부터 만들기

* API 문서나 실제 응답 JSON을 먼저 확인해야 함

### 2) 모든 값을 옵셔널로 만들기

* 오류를 숨기는 데만 집중하면 필요한 값이 빠져도 알아차리기 어려움

### 3) 숫자처럼 보이는 문자열을 숫자로 착각하기

* `"3"`은 문자열이고 `3`은 숫자임

### 4) 중첩 구조를 놓치기

* JSON에 객체가 중첩되어 있으면 Swift 모델도 그 구조에 맞춰야 함


<br>
<br>



# 3-7 전체 흐름 예시

서버에서 다음 JSON을 받았다고 하자

```json
{
  "character_id": 1,
  "character_name": "치이카와",
  "nickname": null
}
```

Swift 모델은 다음처럼 만들 수 있음

```swift
struct Character: Decodable {
    let characterId: Int
    let characterName: String
    let nickname: String?

    enum CodingKeys: String, CodingKey {
        case characterId = "character_id"
        case characterName = "character_name"
        case nickname
    }
}
```

그리고 받은 `Data`를 디코딩함

디코딩에 성공하면 `character`는 Swift의 `Character` 값이 됨  
이후에는 `character.characterId`, `character.nickname`처럼 프로퍼티에 접근해 사용할 수 있음

`nickname`은 옵셔널이므로 값을 화면에 표시하거나 사용하기 전에 값이 있는지 확인해야 함

```swift
if let nickname = character.nickname {
    print(nickname)
} else {
    print("별명이 없음")
}

```swift
do {
    let character = try JSONDecoder().decode(Character.self, from: data)
    print(character.characterName)
} catch {
    print("디코딩 실패:", error)
}
```

여기서는 다음을 확인할 수 있음

- JSON의 `character_id`를 Swift의 `characterId`에 연결
- JSON의 `character_name`을 Swift의 `characterName`에 연결
- `nickname`은 `null`일 수 있으므로 옵셔널로 선언
- 디코딩 실패 가능성이 있으므로 `do-catch`로 처리

<br>
<br>




# 3-8 정리

* `CodingKeys`는 JSON 키와 Swift 프로퍼티 이름을 연결
* 응답에서 빠지거나 `null`일 수 있는 값은 옵셔널로 표현
* JSON 키, 자료형, 중첩 구조가 모델과 맞지 않으면 디코딩 오류가 날 수 있음
* 오류가 발생하면 실제 응답 JSON과 모델 구조를 비교
* 필수 값과 선택 값은 API 문서를 기준으로 구분해야 함
