## 싱글톤 패턴

<br>

# 01 싱글톤 패턴이란?
→ 싱글톤 패턴은 특정 클래스의 인스턴스를 애플리케이션 전체에서 하나만 생성하고 **어디서든 같은 인스턴스에 접근할 수 있도록** 하는 디자인 패턴임

> **이러한 싱글톤 패턴은 두 가지 목적을 가짐 ‼️**
> 1. 인스턴스 생성을 하나도 제한
> 2. 생성된 인스턴스에 전역적으로 접근할 수 있게 함

### 구성요소
1. **하나의 인스턴스** : 클래스 내부에선 객체를 하나만 생성하고 저장 (`static let shared`)
2. **외부 생성 제한** : 외부에서 직접 인스턴스를 만들지 못하도록 생성자를 제한 (`private init()`)
3. **공용 접근 지점** : 외부에서 유일한 인스턴스에 접근할 수 있는 방법을 제공

하지만 여러 곳에서 접근하더라도 실제 객체는 하나만 존재

# 02 일반 객체와 싱글톤 객체의 차이
일반적인 클래스는 인스턴스를 **생성할 때마다** 새로운 **객체가 만들어짐**
```swift
let stroe1 = SnackStore()
let store2 = SnackStore()
```
이 경우 `store1`과 `store2`는 서로 다른 간식 창고임 !! \
반면 싱글톤을 사용하면 같은 창고를 사용하게 됨 = 같은 객체
```swift
let store1 = SnackStore.shared
let store2 = SnackStore.shared

store1 === store2 // true
```

# 03 싱글톤 패턴의 장단점
### 🍀 ===== 장점 ======
### ① 하나의 상태를 공유할 수 있음
간식의 개수를 하나의 객체에서 관리 가능함
> 우사기가 사탕을 하나 먹었음
> = 공용 간식 창고의 사탕 개수가 감소함
> 하치가 확인함
> = 감소한 사탕 개수를 확인 가능
### ② 객체를 여러 번 만들 필요가 없음
간식 창고가 하나만 있으면 됨므로 창고를 **계속 만들 필요가 없다**
### ③ 어디서든 접근하기 쉬움
치이, 하치, 우사기가 **모두 같은 간식 창고에 접근**할 수 있음

---

### 👻 ===== 단점 =====
### ① 전역 상태가 됨
누가 간식을 먹었는지 기록하지 않으면 간식 개수가 언제 바뀌었는지 알기 어려움 (앱의 여러 곳에서 로그인 상태나 설정값을 변경하면 **값이 언제 바뀌는지 추적이 어려움**)
### ② 결합도가 높아짐
여러 클래스에서 참조하게 되면 해당 객체와 강력하게 결합됨 즉, 향후 다른 객체로 바꿀 때 모든 코드를 수정해야해서 **의존도가 높아짐**
### ③ 테스트하기 어려움
테스트 서버로 테스트를 하고 싶어도 이미 정해진 걸 써야함

# 04 싱글톤을 사용하기 좋은 경우
애플리케이션 전체에서 하나만 존재하는 것이 자연스러운 객체에 사용 가능
- 로그 관리자
- 캐시 관리자
- 네트워크 관리자
- 사용자 세션 관리자 등


<sub> ↳ 먼작귀로 비유하자면 치이, 하치, 우사기가 함께 사용하는 공용 간식 창고


단순히 여러 곳에서 사용하고 싶다는 이유로 싱글톤을 사용해서는 안 되고 정말 **인스턴스가 하나만 존재해야하는지 판단 먼저** 해야함

# 05 싱글톤과 의존성 주입
싱글톤은 클래스 내부에서 객체를 **직접** 가져옴
```swift
// 로그인 화면이 네트워크 관리자 객체를 직접 가져와 사용하는 방식
final class LoginViewModel {
    func login() {
        NetworkManager.shared.requset() // 요청
    }
}
```
* 이 방식은 사용하기 쉽지만 `LoginViewModel`이 `NetworkManager`에 강하게 의존하게 됨


반면 의존성 주입은 필요한 객체를 외부에서 전달 받음
```swift
// 테스트 할 때 실제 네트워크 관리자 대신 까짜 네트워크 객체를 전달할 수 있음
final class LoginViewModel {
    private let networkManager: NetworkManager

    init(networkManager: NetworkManager) {
        self.networkManager = networkManager
    }

    func login() {
        networkManager.request()
    }
}
```


# 06 정리
* 싱글톤 패턴은 하나의 인스턴스만 생성하고 여러 곳에서 공유하는 디자인 패턴
* 먼작귀로 비유하면 치이카와, 하치와레, 우사기가 하나의 공용 간식 창고를 사용하는 것


실제 개발에선 다음과 같은 객체에 사용
* `NetworkManger`
* `SessionManager`
* `UserDefaults`
* `FileManager`
* `URLSession`


#### 🍀 장점
* 인스턴스 <mark>중복 생성 방지</mark>
* 공통 상태를 공유 가능
- 전역적으로 접근 가능

#### 😈 단점
- <mark>전역 상태가 됨</mark>
- <mark>결합도(의존도)가 높아짐</mark>
- 테스트하기 어려울수도 있음

### ⇒ 따라서 싱글톤은 <mark>**반드시 하나만 존재해야하는 객체에 한정해서 사용**</mark>하는게 좋음
